# ADR-0008: Wave 2A Domain, Background Service, and Session Control State Machines

- **Status**: Accepted
- **Scope**: `packages/host/src/` (`intake*.ts`, `signals/types.ts`, `linear-types.ts`, `permission-agent-types.ts`, `fuse/types.ts`, `main-check*.ts`, `understanding-runtime.ts`, `repository-briefings.ts`, `repository-graphs.ts`), `apps/mobile/src/features/session/useSessionControl.ts`, `apps/web/src/session-control.ts`

## Context

Across host domain models, background runtime services, and client session-control hooks, mutually exclusive states were previously encoded as optional properties and parallel boolean flags (`IntakeRecord`, `IntakeMessage`, `IntakeSlackSurface`, `ProjectSignal`, `LinearTrackingView`, `PermissionReview`, `PermissionHandled`, `HeadlessSessionStatus`, `FuseTripRecord`, `MainCheckResult`, `MainCheckService`, `UnderstandingRuntime`, `RepositoryBriefings`, `RepositoryGraphs`, and mobile/web `useSessionControl`). Encoding each as a compile-time discriminated union makes illegal field combinations unrepresentable and allows removing inline prose comments across all 14 refactored files.

## Decisions

### 1. Intake domain, thread framing, and Slack surface (`intake-types.ts`, `intake.ts`, `intake-slack.ts`)
- **Discriminated unions**: `IntakeMessage` discriminates on `status` (`"pending"` with `uncertain?`/`nextAttemptAt?`/`error?`, `"sent"` with `ts: string`, `"failed"` with `error: string` and optional `uncertain?`). `IntakeRecord` discriminates on `state` (`"skipped"` requires `skipReason` and forbids `missionId`/`thread`/`request`/`closure`, `"queued"` allows optional `rule`/`holdReason`/`thread`/`request`, `"started" | "finished"` require `rule` and `missionId`). `IntakeSlackSurface` replaces 7 scattered fields with `SurfaceState` (`idle` | `verifying` | `failed` | `running` | `closed`).
- **Prompt injection and outbound redaction**: `intakeObjective` retains only owner messages (`botId === undefined && user === ownerUserId`). `markedThread` normalizes all Unicode line breaks to `\n`, drops empty lines, prefixes every physical line with `owner |`, `other N |`, or `bot |`, and caps per-message text (`entryCap = 4000`) so embedded newlines cannot spoof instructions or starve newer messages. `outboundText` and `failureSummary` redact local filesystem paths, `file://` URLs, and IPv4 literals before sending to Slack or Linear; full errors remain in host logs only.
- **Slack protocol and delivery invariants**: Slack mention markup (`<@U…>`/`<@W…>`) identifies users rather than bot IDs; Slack omits `channel_type` on `app_mention` and delivers both `message` and `app_mention` (owned by `app_mention`). `deliver` persists `uncertain: true` before `post` and checks `${issueId}:${key}` in the thread before reposting on retry. `addParts` runs `outboundText` before splitting into numbered parts persisted once by key. Inbound `block_actions` validate owner identity, bound thread, persisted question block/element/options, reconcile uncertain `pending` or `failed` question messages against `${issueId}:${key}` and `ts` in the thread, and require confirmed `message.ts`.
- **Lifecycle, routing, and persistence**: Slack timestamps convert to integer microseconds/milliseconds via string splitting to avoid float rounding. `pendingMentions` pins a generated UUID per `(channelId, ts)` until stored. `routable` and `request` are saved before classification/creation so config toggles or retries never strand queued work; `poll()` coalesces cycles and `requestFromSlack` triggers an extra cycle if a cycle already passed `file`. Answer missions bypass `maxActive` and Linear tracking; `deadlineStopped` keeps the record `"started"` (deduplicating notices by `deadlineAt` via `deadlineNoticeFor`); `watchRecord` defers closure pause while deadline-stopped and seeds `tracked` for legacy host-filed records. `IntakeSlackSurface` posts only to `record.thread`, rethrows `fileDirect` errors to withhold Socket Mode acknowledgement, persists chosen mission `call` + `revision` before execution (retrying `stale-mission-revision` once), and routes ambiguous multi-record threads by `Qn` → identifier → `"answer"` → single unfinished → newest finished.

### 2. Project signals, Linear tracking, and spend fuse (`signals/types.ts`, `linear-types.ts`, `fuse/types.ts`)
- **Signals (`signals/types.ts`)**: `ProjectSignal` discriminates on `kind` (`"owner"` requires `text` and forbids `commit`/`runId`; `"revert" | "external-commit" | "delivery-landed"` forbid `text` and carry optional `commit`/`runId`). The inbox is passive: `SignalReader` exposes synchronous non-throwing reads (`undefined` / `[]` when unreadable so consumer cursors stay unchanged) and `PendingWake` caps queued signals at `maxPendingWakeSignals = 20`.
- **Linear (`linear-types.ts`)**: `LinearTrackingView` discriminates on `status` (`"synced"` requires `issue` and forbids `reason`/`retryAt`; `"blocked" | "error"` require `reason` and retain any linked `issue`; `"pending"` retains any previously linked `issue` across refreshes, queued comments, and parent gating). Linear workflow state stays independent of local execution status; rate-limit `basis` records `"retry-after"`, `"reset"` (probed at most every 5 minutes), or `"fallback"`, without exposing credentials or issue text in `LinearBridgeStatus`.
- **Fuse (`fuse/types.ts`)**: `FuseTripRecord` discriminates on `scope` (`"host"` forbids `projectId`; `"project"` requires `projectId`) and pairs `closedAt`/`closedBy`. Host owner halt checks precede `FuseGate`; `held()` evaluates multi-project halts and `refund()` returns process-local admissions refused by halt before session creation.

### 3. Permission agent contract (`permission-agent-types.ts`)
- **Discriminated unions**: `PermissionReview` discriminates on `verdict` (`"allow"` | `"reject"` with `code` | `"owner"` with `interruptClass`). `PermissionHandled` discriminates on `handled` and `result` so `code` and `interruptClass` cannot coexist. `HeadlessSessionStatus` discriminates on `state` (`"served"` allows `waiting` and forbids `reason`; `"admitted" | "not-served"` require `reason` and forbid `waiting`).
- **Authority and evaluation**: `PermissionRequester` is constructed exclusively from authenticated host records; `projectId` resolves coverage and `assignment` survives member replacement/revision. `binding()` hashes policy, tiers, classes, rules, and profiles; `readRules` resolves each path once without reject history so class and raise rules observe one filesystem state. `held()` runs before every review turn (`PermissionReviewHeld` aborts with no recorded decision); `canAllow: false` discards model allows; `ownerClass` returns a class only for class rules or `owner` verdicts (never model text or `undeliverable`).
- **Delivery and headless execution**: `check()` runs live checks right before sending keys, `answer()` re-reads `current()` under the control lease before the first key, `uncertain` deliveries are never retried, and `fence()` fences in-flight deliveries on authority loss. Headless shadowed allow rules outranked by class rules wait for the owner.

### 4. MainCheck rules and service lifecycle (`main-check-state.ts`, `main-check.ts`)
- **Discriminated unions**: `MainCheckResult` discriminates on `outcome` (`"passed" | "failed"` forbid `reason`; `"interrupted"` requires `time-limit | halt | host-stop`; `"error"` requires `workspace | copy-changed | command-unavailable | stop-unconfirmed`). `MainCheckService` replaces 7 scattered booleans/optionals with `ServicePhase` (`unstarted` | `running` | `closing` | `closed`), preserving record commits during `closing` until unwritten finishes flush and rejecting commits once `closed`.
- **Process, witness, and scheduling invariants**: Pure transitions in `main-check-state.ts` write full records synchronously before updating memory; unreadable records halt host-wide admissions until readable. Commands lead their own session/process group; stops signal the group only while the leader lives (`STOP_BOUND_MS = 10s`); `recording` is saved before a command starts and, while the check runs, cleared only once every started command's start-token read has settled (a token it finds is saved; a read that finds the process gone, or fails, saves none); the finish writes the retiring entry without the flag and a finished check's later saves never add it, because by then the witness holds every started command's pid as a group and session id (a command leads both), and a missing pid is all the flag guards, so a host stop after the finish leaves no hold that only a reboot clears (INF-502); R7 deletes a copy only after a clean census with no active `tails` and no same-boot `recording` entry from a prior process. The census excuses an `unreadable` process only when the copy's anchor (`main-check-anchors.ts`: a sealed file per copy under `main-check-anchors/`, outside the directory an earlier release lists, schema version 1, at most 256 `{pid, start}` entries) names the same pid and start token on the boot of both the entry and the host; the anchor is taken only from the gate census of the admission pass, over `main-check-gate` under the team root (a path no copy uses, so no process has a reason to name it; this matters because the census reports a process that names its path by `command-line` before `unreadable`), never at recovery, because a census after a restart can see the run's own hidden processes. A missing, unreadable or mismatched anchor excuses nothing. After a boot change Linux excuses every `unreadable` process and macOS none, because a macOS boot id can change with the clock (INF-426). The anchor is deleted only after the retirement's record write landed, so a failed write retires at a later pass, and orphans are swept once per start when every record reads. Halt is polled every 2s, notices coalesce with a 60s flight window, and absent health/`told` counts as `"passed"`.

### 5. Host background services (`understanding-runtime.ts`, `repository-briefings.ts`, `repository-graphs.ts`)
- **Lifecycle unions**: Each service replaces scattered `closed`/`running`/`polling`/`timer`/`closeWaiters` fields with an explicit `Lifecycle` discriminated union (`idle` | `draining` | `closing` | `closed` in `UnderstandingRuntime` and `RepositoryBriefings`; `idle` | `running` | `closed` plus `LanePhase` in `RepositoryGraphs`), preserving shutdown bounds (`1500ms` timeout in `UnderstandingRuntime`; rejecting queued `pending` waiters and draining the active `drain()` loop in `RepositoryBriefings`).
- **Understanding runtime**: Legacy single-file `runtime.sealed` migrates to per-workspace `.sealed` files while staying authoritative until every per-workspace write succeeds. `readWithContexts` clears stale `budget-limited` states after midnight and validates bindings before exposing contexts. Attempt deadlines reserve time for final source re-check, reject timeouts before aborting controllers, and drop unconfirmed engine output if revalidation fails or catalog plans change before publication.
- **Repository briefings**: `discoveredBefore` baselines prior exited sessions without an unbounded ID set; journal reads window recent pages; automatic jobs recollect activity after debounce/cooldown before invoking `jevcode auto` and capture/revalidate retention before persisting; `disabled` maps to `unavailable`, not `failed`.
- **Repository graphs**: `RepositoryGraphs` parses untrusted builder stdout with `repositoryCodeMapSchema` and `MAX_CODE_MAP_BYTES` (256 KiB), enforces exact project roots for `shared` lanes and `workspaceRoot` containment for feature lanes, decodes stdout as a UTF-8 stream, resolves only waiters matching the built head, and preserves each lane's last valid map across failed or busy refreshes.

### 6. Mobile and Web session control leases (`useSessionControl.ts`, `session-control.ts`)
- **Lease phase**: Both hooks encode lease ownership in `LeasePhase` (`unheld` | `claiming` | `held` | `releasing`) while keeping their public return shapes backwards-compatible.
- **Fencing and lifecycle**: Both bump a monotonic `revision`/`generation` on every local transition and after `claim`/`renew`/`release` completions so stale polls cannot revoke newer control. Mobile shares one control instance across `Brief` and `Terminal` routes (`focus` count drops on `setTimeout(0)` to bridge route switches), suspends renewals in background while checking expiry synchronously in `leaseId()` and foreground return, and retries lost in-flight renewals on foreground return (`renewOnForeground`). Web bounds `releaseRequest` retries by `lease.expiresAt`, preserves `reconnecting` across transient claim errors, and renews or reclaims immediately on tab visibility or `online`.

## Consequences

- `packages/host/src/intake.ts`, `intake-slack.ts`, `main-check.ts`, `main-check-state.ts`, `understanding-runtime.ts`, `repository-briefings.ts`, `repository-graphs.ts`, `permission-agent-types.ts`, `signals/types.ts`, `linear-types.ts`, `fuse/types.ts`, `intake-types.ts`, `apps/mobile/src/features/session/useSessionControl.ts`, and `apps/web/src/session-control.ts` now enforce phase/variant invariants at compile time and carry zero prose comments under `scripts/check-comments.mjs`.
- `scripts/comments-baseline.json` is lowered accordingly while `scripts/file-size-baseline.json` stays within every existing baseline.
