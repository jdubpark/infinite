# ADR-0017: Host Eval, Evidence, Objective, Outcome, and Routing Invariants

- **Status**: Accepted
- **Scope**: `packages/host/src/` (`eval*`, `evaluator-profiles.ts`, `evidence/**`, `objective*`, `outcome*`, `routing*`)

## Context

These five host subsystems encode safety, cryptographic isolation, state-machine ordering, durability, and statistical invariants across eval execution, encrypted SQLite evidence storage, objective records, outcome ledgers, and adaptive model routing. Their rationale was previously scattered across 1,301 inline comment blocks in 87 files. This ADR consolidates every non-obvious architectural, security, concurrency, and schema invariant by subsystem so those source files carry zero prose comments under `scripts/check-comments.mjs`.

## Decisions

### 1. Eval, Trial Lifecycle, Mining, Validation, and Evaluator Independence (`eval*`, `evaluator-profiles.ts`)
- **Asynchronous capture outside command scopes (`eval-capture.ts`, `eval-git.ts`, `eval-rules.ts`)**: `TaskCapture` observes integrated tasks and approvals synchronously without throwing or mutating run records, running Git reads asynchronously outside any caller `commandScope`. Git reads share a bounded stalled-call budget; empty reference patches (`bytes.length === 0`) are rejected as missing because captured tasks require at least two files; base-branch provenance requires `merge-base --is-ancestor` against the mirror head. Promotion (`promotion`) evaluates gates in strict order: pending facts → ledger row → decision use → no `same-model-review` → non-partial patch → approved reference with no later overlapping changes → proven base → valid risk.
- **Root merging, holdout split, and duplicate suppression (`eval-groups.ts`, `eval-sets.ts`, `eval-calibration.ts`)**: `mergeRoots` folds roots into the smallest ID and preserves any `devOnly` mark; `mergedSet` remains `holdout` (assigned at `HOLDOUT_THRESHOLD = 1_288_490_189`, 30% of `2^32`) only when every merged part was `holdout` and none was `devOnly` or `exposed`. Captured `candidate`/`valid` tasks automatically reject/retire overlapping mined tasks in the same root (`duplicate-of-captured`). Reading `calibrationPairs` marks returned task groups `exposed` in the same transaction; `rotateHoldout` skips projects with unreported `confirm` jobs (`eval_jobs_unreported`).
- **Bounded base-branch mining (`eval-miner.ts`, `eval-mine-git.ts`, `eval-mine-rules.ts`)**: `Miner` processes at most 50 commits per pass, committing each commit's decision and cursor individually. When `forward` is pruned by a history rewrite and garbage collection, `Miner` decides `HEAD` first to advance `forward` past a capped backfill (`MINING_BACKFILL_MAX = 2000`) and restarts backfill from `HEAD`'s first parent. Commits with binary files, UI changes, missing test+non-test pairs, or unreadable/oversized diffs are rejected.
- **Validation and linear report parsing (`eval-validate-rules.ts`, `eval-report.ts`)**: `nextRound` requires three consistent runner reports (`R1`, `R2`, `R3`) passing the exact same expected case keys `E` and baselines (`B1`, `B2`) that fail (`notPassedOf`) the exact same non-empty subset of `E`. Exit codes alone can reject but never validate a task. JUnit XML and TAP 13/14 parsers scan in a single linear pass, reject `<!DOCTYPE` / `<!ENTITY` / `<!` declarations, and key cases by `sha256` (keeping the worse status on duplicates). `restoreLists` intersects only grader-printed diff paths; `focusedArgv` prefixes paths with `./` so filenames never parse as CLI flags.
- **OS account isolation and trial pump (`eval-grader.ts`, `eval-identity.ts`, `eval-jobs.ts`, `eval-trial-jobs.ts`, `eval-trial-pump.ts`, `eval-trial-rules.ts`, `eval-trial-store.ts`, `eval-comparison.ts`, `eval-priors.ts`)**: Grader and eval member execute behind `sudo` launchers under separate OS accounts. `launch` serializes one command at a time per channel (except bypass `stop` calls), never signals child processes directly from the host, and passes proxy URLs over `stdin` rather than arguments or environment variables. `TrialPump` runs one live trial or calibration judgement host-wide (alternating when both are ready, holding calibrations with `"start-up"`, `"another-job"`, or `"eval-identity"` when blocked), drops/voids leftover rows (`voidHost` starts preparing rows first so they count as started) and runs startup clean until both stop and clean succeed, releases transient environment failures (`halt`, `storage`, `grader-failed`, `eval-failed`, `bundle-missing`, `mirror`) without burning an attempt while blocking on surviving processes (`eval-processes-alive`), pauses a job after 3 consecutive voids, records session usage cost before deleting replay sessions, and keeps `watch()` outside the validation chain so slow validations do not delay trial timeouts. Only final non-void original trials are eligible for reuse in `compare` jobs, and reused copies are excluded from prior exports (`eval-comparison.ts`) so trials are never double-counted.
- **Evaluator independence (`evaluator-profiles.ts`)**: `autonomyReady` requires at least one evaluator profile with a known model family distinct from the coordinator's; `chooseIntentChecker` also excludes the plan author's family and rate-limited providers; `chooseEvaluator` excludes coordinator-family profiles, the family of every project manager that ran (`managers`; an unknown manager family makes none eligible), integrated task authors (`sameModel`), rate-limited providers, and previously failed profiles while deprioritizing (not excluding) run reviewers (`alsoReviewed`), over `evaluatorProfiles` (which falls back to at most 4 deduplicated strong reviewer/escalation profiles when `lineup.evaluators` is absent). Mission subteams and handoff runs force intent checks and verdicts off.

### 2. Evidence Store, Blackboard, Outbox, Secret Scanning, and Permission Journal (`evidence/**`)
- **Single-writer encrypted SQLite and cross-process reader (`store.ts`, `reader.ts`, `crypto.ts`, `types.ts`)**: The host process is the sole writer (`DEFAULT_BUSY_TIMEOUT_MS = 250`). New databases build under `<file>.creating-<pid>-<uuid>` and link atomically; stale temp files are removed only when `kill(pid, 0)` returns `ESRCH`. Opening verifies key version and vault key check on both read-only and writer connections before any `PRAGMA` or migration. `EvidenceReader` opens read-only deferred transactions for worker processes with `READER_REOPEN_MS = 5_000` cooldown after open failures.
- **SQL sandboxing, blind indexes, and error redaction (`store.ts`, `crypto.ts`)**: `checkedSql` / `allowedStatements` splits statements matching SQLite's lexer and rejects transaction-ending verbs, `ATTACH`, `VACUUM`, `PRAGMA`, and Tcl-style `$name(...)` parameters; `transactionOpen` falls back to a `BEGIN` probe and fails closed; `plainParameters` copies primitives/buffers without invoking caller getters; module hooks must be synchronous. Plain SQL columns hold only opaque IDs, enums, numbers, timestamps, or domain-separated keyed HMAC blind indexes (`blindIndex`); free text and paths live strictly inside AES-256-GCM sealed canonical JSON payloads (`sealRow`). `failureToken` maps errors to a closed token set so paths and caller text never reach logs.
- **Event outbox (`outbox.ts`)**: Run events commit before projectors advance. Each registered projector runs synchronously inside its own transaction per page, commits rows and cursor atomically, blocks permanently for the process lifetime if its stored definition or cursor mismatches, and records `lost` counts inside `deleteRun` before events are deleted.
- **Blackboard mirroring, member posts, and reads (`blackboard.ts`, `entry-reads.ts`, `entry-types.ts`, `host-entries.ts`, `member-entry.ts`)**: `Blackboard` mirrors host entries from saved run records without mutating runs, strips review rubrics (`withoutRubric`), and backs off failed runs/writes for 1 minute. Member posts (`contract`, `finding`, `blocker`, `handoff`) are capped at `MAX_MEMBER_ENTRIES = 400`, validated against member binding/role/task, and resolved via order-independent supersede rules (`settleSupersedes`, ignoring withdrawn entries). Default member reads query `ADDRESSED_ENTRY_KINDS` via a partial index (`entries_active_by_run`) so host `report`/`check` entries never push member posts out of the window; `getForMember` checks `MAX_SERVED_BODY_BYTES` before decryption; `memberHeadOf` strips run, revision, scope, and author member IDs.
- **Secret scanning (`secret-scan.ts`)**: Rejects provider token shapes, host-issued `VERSION.CLAIMS.MAC` / `VERSION.EXPIRES.MAC` tokens (requiring exact 43-char base64url HMAC-SHA256 MACs so 64-char build/cache IDs pass), session environment credentials (including URL passwords), and loopback hook URLs across object keys and values without echoing matched text.
- **Permission journal and replay isolation (`permission-journal.ts`, `permission-repeat-count.ts`, `permission-measurements.ts`)**: The journal is append-only, ordered strictly by monotonic `seq` (never wall-clock timestamps), and deliberately omits a `deleteRun` hook. Replay verdicts stay within one task without chaining (`replaySource`) and forbid replaying a strong-reviewer verdict to a requester of the same or unknown model family (`replayEligible`). `hasRejectHistory` persists across unlocks, reopens, and task closes to keep subsequent requests on the strong tier. `raisedRepeatCount` deduplicates repeat counts by sealed `requestDigest` since the latest unlock or reopen. Owner marks are immutable rows with idempotent `requestId` conflict checks; replay candidates strip model notes; `PermissionMeasurements` isolates replay evaluation turns from the decision journal.

### 3. Objective Records, Intent Checks, Corrections, Proposals, and Receipts (`objective*`)
- **Sealed record, digest bounds, and reverse-undo versioning (`objective-record.ts`, `objective-write.ts`, `objective-types.ts`)**: Records seal with `recordDigest` over all fields except `digest` and `log`; `cappedBytes` bounds operational state independently of statement, non-goals, owner evidence, and `c0` statement. Log entries over 2 KiB store a digest+size reference (`logValueOf`). Prior versions are rebuilt by undoing log entries in descending `seq` (`rebuildVersion`) with hash-verified `addedDigest` and `replaced` handle index restoration (`withHandle`). Stored reads are strict and never auto-repair (`readStoredRecord`).
- **Ownership and atomic mutations (`objective-goals.ts`, `objective-runs.ts`, `objective-holder.ts`, `objective-ops.ts`)**: Goal records live on the goal (goal-cycle runs, mission subteams, and handoff runs hold no own record); standalone run records live on the run. `GoalRecordPort.write` enforces expected version (`objective-version-stale`) and restores the in-memory record on save failure; `correctGoalObjective` computes a corrected record without mutating the holder so receipt and event persist together. `applyOwnerOps` validates all ops atomically against input-record targets, verifies that each criterion fits inline in its 1-byte-longer `retired` log form, and refuses ratings without a reviewed cycle or status overrides on host-tested assumptions.
- **Directions, intent checks, proposals, and digests (`objective-intent.ts`, `objective-proposals.ts`, `objective-digest.ts`, `objective-receipts.ts`, `objective-register.ts`, `objective-citations.ts`, `objective-cli.ts`)**: Only owner steering/corrections (including owner GitHub reviews) become directions; connector/coordinator steering is excluded (`recordSteering`). `screenIntentReport` filters bad/secret/uncited items idempotently; `applyIntentReport` drops invalid report items without throwing while `assertLogRoom` enforces `CORRECTION_LOG` (380 entries / 210 KiB out of 400 / 256 KiB, throwing `objective-log-full` if exceeded) to leave 20 entries / 46 KiB reserved for steering/owner corrections. Blocking `intentDecision` rebuilds deterministically from `waits` + `decisionId` across restarts, and `answerIntentQuestions` is idempotent on replay. `applyProposals` applies one member journal page per version step within per-member and shared caps, dropping secrets silently. `registerDigestFor` excludes member-only assumptions and stops on whole items at byte/count caps; `applyReceipts` updates only unpinned assumptions when status changes (`first` receipt wins); `objective-cli.ts` caps file reads at 64 KiB and validates inputs before issuing HTTP requests.

### 4. Outcome Ledger, Backfill, Signals, Base-Branch Scanning, and Roll-Ups (`outcome*`)
- **Deterministic projector and disposition precedence (`outcome-projector.ts`, `outcome-rules.ts`, `outcome-store.ts`)**: `outcomeProjector` maps run events in `seq` order using event timestamps (never wall clock), stalls until `configurations` is ready, skips outcome/member rows for `duel` (judge) runs, computes `linkAfterPaths` in memory without persisting paths, and freezes integrated rows on first settle while still resolving prior correction-round links. `replaces` precedence lets attempt faults override host stops, lets question/blocker reports override halt stops (because member journals flush asynchronously), and lets integration/completion override all. `deleteRun` stamps `run_deleted_at` while keeping rows readable until the 730-day retention sweep (`sweepExpiredOutcomes`).
- **Server-derived blind indexes, points, and non-production rows (`outcome-store.ts`, `outcome-signals.ts`)**: `writeOutcome` derives blind indexes, `goalRef`/`missionRef`, `featureMapRef`, and `routingPoint` (`start` vs `escalation` along replacement chains; sentinel attempt 0 → `null`) server-side from sealed payloads. `legacy` and `replay` rows never enter `ROUTING_SOURCES` (`["production", "duel"]`), and `replay` levels remain `null`.
- **Startup backfill and legacy imports (`outcome-backfill.ts`, `outcome-legacy.ts`, `outcome-import.ts`)**: `outcomeBackfill` writes all active non-settled qualifying runs synchronously on first tick before serving so readers never see partial live history, never overwrites event-derived rows or existing signals, never freezes `accepted: 0` from non-approved reviews, and marks unbindable legacy records (`skipped: -1`) without retrying. `planLegacyBatch` achieves order-independent results via forward/reverse supersede marks and refuses collisions with host outcome IDs.
- **Base-branch scanning and fail-closed signal reads (`outcome-scan.ts`, `outcome-hold.ts`, `outcome-signals.ts`)**: `BaseScanner` serializes per-project scans using `UNREAD_LIMIT = 8` fetch history (`continues`) to detect history gaps or rewrites; `matchReverts` declines matches when history order is unprovable (`older` or `unsure`), and `matchLandings` rule-3 tree matches require chronological proof. `SCAN_COMMAND_LIMIT = 600` bounds adversarial commit messages; `applyScan` uses optimistic `expectedSeq` and monotonic timestamps; `recomputeAfterScan` skips runs with unreadable signals so one corrupt seal cannot stall a project's scan, whereas `ownerSignal` / `everySignal` fail closed on unreadable signals.
- **Cost, gauges, and roll-ups (`outcome-cost.ts`, `outcome-cells.ts`, `outcome-rollup.ts`, `outcome-gauges.ts`)**: `sessionCostOf` returns `undefined` for unmeasured sessions and `{ usd, tokens, complete: false }` for partial coverage (never `0`), which `completeCost` / `costOf` discard; non-metered providers record no spend, unreadable usage ledgers fail 503 `unavailable`, and `integrationGauge` computes concurrency/staleness purely from host run state.

### 5. Adaptive Routing Policy, Posterior Scoring, Exploration Guards, and Decision Store (`routing*`)
- **Policy resolution, pinning, and shadow period (`routing-policy.ts`, `routing-auto.ts`, `routing-recorder.ts`, `routing-rules.ts`)**: Effective mode follows saved mode, then autonomous default (`shadow` until `periodEndedAt`; supervised projects default `off`). `periodEnd` latches once after 50 recorded starts and 14 days from the first start (`computedPeriodEnd`) and never moves. `algorithmVersionOf` is 2 when `escalation` or `scout` points are enabled; `policyDigest` hashes canonical `{ algorithmVersion, rewardVersion, mode, knobs }`. Runs without covered start profiles refuse 409 `routing-no-eligible-profile` under saved `auto` and fall back to `shadow` under autonomous defaults.
- **Screening, hierarchical posterior, and deterministic sampling (`routing-choice.ts`, `routing-posterior.ts`, `routing-sample.ts`, `routing-reads.ts`)**: `screenProfiles` removes (1) contributor profiles unless `allowContributor`, (2) reviewer's model, and (3) rate-limited providers in fixed order. `posterior` sorts rows by `outcomeId`, weights applied `auto` starts at `1` vs coordinator choices at `CHOSEN_WEIGHT = 0.5` and provisional `held === null` observations at `0.5`, applies exponential age decay, and chains priors tenant → project → cell (`strength <= 20`, earlier mass capped). `choose` applies deterministic fallbacks (`default-all-limited`, `single-candidate`, `greedy-point`, `greedy-risk` with `mean - sd` and `3x` success value) before `sha256`-seeded Thompson sampling (`betaSample`, falling back to mean with `fallback: true`, recorded on `CandidateRecord` as `samplerFallback: true`, on gamma rejection exhaustion). Scouts select lowest `tierCost` without sampling (`chooseScout`).
- **Exploration guards and idempotent decision storage (`routing-guards.ts`, `routing-points.ts`, `routing-store.ts`)**: `start` decisions check `pausedAt`, `spareAttempts`, and `shareWindow` (`E + 1 <= s*(N + 1) + eps` over applied or recent 7-day pending starts), converting guarded picks to `greedy` while preserving candidate samples. Decisions enforce `DECISION_BUDGET_MS = 250` and `PAYLOAD_LIMIT_BYTES` before `INSERT ... ON CONFLICT(key) DO NOTHING` keyed by `(runId, revision, taskKey, point, ordinal)` with blind-indexed `taskKey`; an already-stored row always governs the run. `routingProjector` settles `pending` rows to `applied` or `released` from run events without opening sealed payloads, and `sweepExpiredDecisions` expires aged rows without throwing.

## Consequences

- All 87 target host files across `eval*`, `evidence/**`, `objective*`, `outcome*`, and `routing*` reach zero prose comments under `scripts/check-comments.mjs` with zero AST or transpiled output changes.
- Ten rationalized workarounds/incomplete items discovered during the sweep are captured separately as Linear-ready follow-up items rather than left as inline excuses.
