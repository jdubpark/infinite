# ADR-0018: Test Harness, Simulator, and Verification Invariants

- **Status**: Accepted
- **Scope**: `tests/` (`tests/*.ts`, `tests/fixtures/*.ts`, `tests/fixtures/*.mjs`, `tests/fixtures/*.tsx`)

## Context

The test suite under `tests/` exercises real child processes, UNIX domain sockets, filesystem permission boundaries, privilege-separated shell launchers, seeded crash/fault simulators, and byte-pinned prompt generators. Many test files previously carried inline prose explaining why harnesses deviate from production paths, how seeded simulators define correctness oracles, and why platform-specific bounds apply. This ADR consolidates those non-obvious test invariants so `tests/` stays free of prose comments under `scripts/check-comments.mjs`.

## Decisions

### 1. Socket path bounds and filesystem permission fixtures
- **Short socket directories (`helpers.ts`, `eval-session.test.ts`, `fuse-launch.test.ts`, `session-listing.test.ts`, `mcp-server.test.ts`)**: `Manager` rejects run directories whose IPC socket path exceeds 100 bytes (below the OS `sun_path` limit). Because `os.tmpdir()` on macOS exceeds that length, test harnesses allocate socket-bearing run directories under `/tmp` or short relative paths and clean them up in `finally`.
- **Grant-key directory ownership (`github-boundary.test.ts`, `github-grants.test.ts`)**: Grant-key verification rejects keys whose ancestor directories are world-writable (such as shared `/tmp`). Because tests run unprivileged without root, fixtures create `0o700` roots under `os.homedir()` with `trustedUid` set to the current UID, while separately asserting that the production default (`trustedUid = 0`) and world-readable modes (`0o644`) fail closed.

### 2. Same-user launcher isolation and rewritten shell copies
- **Rewritten shell launcher copies (`eval-launcher.test.ts`, `eval-grader-launcher.test.ts`)**: Installed privilege-boundary scripts (`deploy/ubuntu/eval-command.sh`, `deploy/ubuntu/grader-command.sh`) are never executed directly in tests because `stop` kills every process of the target account and deletes its temporary files. `eval-launcher.test.ts` rewrites `ROOT`, `ACCOUNT`, `EVAL_HOME`, `TEMPLATE`, `EVAL_TMP`, and `STOP_DIRS` (plus isolated System V IPC tables), while `eval-grader-launcher.test.ts` rewrites `ROOT`, `ACCOUNT`, `kill -KILL -1`, and `--nproc=512`, asserting exact line-replacement counts so script edits fail loudly rather than silently leaving production paths active.
  - Every copy except the dedicated end-to-end `stop` case replaces the kill command with `exit 99` so a broken account check fails the test rather than terminating the test runner.
  - Copies drop `prlimit --nproc=512` because Linux counts all threads owned by the real user (causing busy accounts to fail fork, while raising above the hard limit fails with `EPERM`); a cross-platform static check pins the `prlimit` flag on the installed script.
  - Copies substitute isolated per-copy System V IPC table files so pre-existing user objects are not counted or removed; the single full `stop` test compares independent kernel/directory scans (`ownSysV`, `ownEntries`) before running and skips if the user already owns matching objects.
- **Same-user Node stand-ins (`tests/fixtures/eval-command.mjs`, `tests/fixtures/grader-command.mjs`, `tests/fixtures/unsignalled-writer.mjs`, wired via `tests/eval-run-fixture.ts`)**: Host-level replay and validation suites use same-user Node fixtures matching the launcher CLI flag contract (`--root`, `--home`, `--tmp` before operation) without signalling external process groups. `unsignalled-writer.mjs` spawns the `bundle create` writer in its own session over a socket pair so pipe-closure termination (`EPIPE` on macOS, `EPIPE` or `ECONNRESET` on Linux) is tested when group signals cannot reach the child.
- **Real-user canary limits (`eval-run-fixture.ts`, `eval-validate-run.test.ts`)**: Because same-user fixtures share the caller UID, host paths remain readable as the grader account and cannot act as unreadable-canary traps; `seen` hooks capture the passed canary list before clearing it.

### 3. Seeded crash, fault, and differential simulators
- **Team run crash simulator (`tests/fixtures/team-run-sim.ts`, `team-run-sim.test.ts`)**: Models host termination (`HostStopped`) immediately after the *N*th sealed record write while retaining in-flight worker state across restarts. Verifies invariants I1–I7 against a pure request-acknowledgement model: exactly-once acknowledged mutations, idempotent retries with unchanged digest and zero record writes, intermediate state bounds (receipts never written before their mutation), monotonic revisions/cursors, settled-run immutability, zero writes on refusal, and request-ID/revision conflict rejection.
- **Outcome projector fault simulator (`outcome-projector-sim.test.ts`, `outcome-sim-script.ts`)**: Drives real SQLite evidence stores, outbox draining, and projectors under restarts, outbox re-flushes, mid-page rollbacks, dropped events (`ledger.gap`), and duplicate-key deliveries against a direct seq-ordered reference store (P1–P8: differential table equivalence, single-step replay idempotence, disposition and freeze monotonicity, signal/summary count alignment, gap propagation, and monotonic outbox cursors). Scripts preserve TeamService's guaranteed event orderings while exercising every legal cross-thread reorder.
- **Search engine, main check, and goal metrics simulators (`tests/search-engine-sim-script.ts`, `tests/search-engine-sim.test.ts`, `tests/fixtures/main-check-sim.ts`, `tests/fixtures/main-check-world.ts`, `tests/main-check-sim.test.ts`, `tests/fixtures/goal-metrics-sim.ts`, `tests/goal-metrics-sim.test.ts`)**: Deterministic virtual-clock simulators enforce corpus coverage floors (about half of baseline case counts so generator regressions fail) and verify that in-process mutant wrappers trigger their expected invariants (search S0–S14, main-check I1–I10, goal-metrics I1–I5).

### 4. Process-group, drain, and live-transport determinism
- **Process-group signal refusal (`eval-git.test.ts`, `team-command-leader.test.ts`, `team-bundle-stop.test.ts`)**: On macOS, signaling the process group of an exited child is refused; reads must still settle without leaking timers or handles. `team-command-leader.test.ts` chains `setImmediate` after leader reap so the event-loop poll phase stays delayed past the drain timer, deterministically exercising `leftover`/`truncated` output from a lingering holder.
- **Leader-exit witnesses (`process-group.test.ts`, `team-bundle-stop.test.ts`, `tests/leader-exit.ts`, `tests/fixtures/leader-leaves.mjs`)**: The fixture leader records its PID, a holder in its own session that keeps the leader's output open, and a witness in the leader's group with no output, then exits, or ends itself with `SIGKILL` in the `-killed` modes so that only `signalCode` marks the exit. A witness still running after the spawner's stop proves that nothing signalled the leader's group after its exit; a stop that the drain has already settled is skipped rather than counted. In the `running` mode the leader stays up with a group member that ignores `SIGTERM`; a member still running past the stop's escalation delay proves that no `SIGKILL` followed the leader's end. Tests end every recorded process other than the leader by PID in `finally`.
- **Unreadable process baseline (`main-check-earlier.ts`, `main-check-real.test.ts`)**: On Linux, pre-existing login-session processes uninspectable by the census are snapshotted once at startup so copy-retirement assertions distinguish test-owned processes from ambient session daemons.
- **Real PTY and socket frame checks (`terminal-worker.test.ts`, `native-ui.test.ts`, `hybrid-codex.test.ts`)**: Worker lifecycle tests run real PTYs and authenticated hooks asserting only over worker IPC and encrypted journals, and UI takeover tests race stale responses directly against the socket rather than relying on periodic close timers or substituted clocks.

### 5. Contract validators, byte pins, and Node-hosted UI stand-ins
- **Fail-closed schema subset (`tests/wire-schema.ts`)**: Validates team-tool `outputSchema`s against a strict draft-7 subset, pre-scanning the schema and throwing on any unimplemented keyword, `type`, or `format` rather than silently skipping validation (avoiding a cross-workspace JSON Schema dependency).
- **Prompt byte pins (`register-prompt.test.ts`, `config-identity.test.ts`, `team-prompts.test.ts`)**: Strip installation-specific command paths (`<report-command>`, `<entry-command>`) and assert exact SHA-256 prompt hashes so unintended prompt or schema drift fails immediately.
- **Floating-point tolerance (`routing-choice.test.ts`)**: Compares golden draws within `1e-12` to absorb last-bit `Math.log`/`Math.cos`/`**` differences across CPUs and Node builds while catching structural generator changes (gated by `ROUTING_ALGORITHM_VERSION`).
- **CSS warning gate (`web-stylesheet.test.ts`)**: Runs `esbuild.transform` over `apps/web/src/style.css` and fails on any warning, because esbuild CSS minification only warns on syntax errors (such as a dropped brace) and silently shifts subsequent rules into enclosing blocks.
- **Node hook/native stand-ins (`tests/fixtures/react-hooks.ts`, `tests/fixtures/mobile-native.ts`)**: Provide minimal synchronous React hook and Expo module doubles so client state hooks run directly under `node --test`.

## Consequences

- All target `tests/` files (outside the 15 concurrent-wave files) carry zero prose comments under `scripts/check-comments.mjs`, while non-obvious test-harness constraints remain documented here.
- Eight test-harness workarounds/flakiness excuses discovered during the sweep are tracked separately as Linear-ready items for follow-up hardening.
