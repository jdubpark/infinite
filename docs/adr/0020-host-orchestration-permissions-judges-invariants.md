# ADR-0020: Host Orchestration, Permission Agent, Verdicts, Goals, and Judge Invariants

- **Status**: Accepted
- **Scope**: `packages/host/src/` (`autonomy*`, `board-cli.ts`, `delivery-review.ts`, `duel-cli.ts`, `goal-*` excluding `goal-types.ts`, `intent-*`, `judge-*`, `mission-progress.ts`, `mission-read-routes.ts`, `permission*`, `routine-*`, `team-*` excluding `team-types.ts`, `teams.ts`, `verdict-*`)

## Context

These host subsystems enforce owner authority, fail-closed autonomy and permission boundaries, delivery lineage, isolated workspace execution, objective intent checks and verdicts, standing goal progression, blind judge calibration, and bounded agent reporting/prompting. Their rationale was previously distributed across 1,239 inline comment blocks (2,281 comment lines) in 84 files. This ADR consolidates every non-obvious architectural, security, concurrency, durability, and protocol invariant so those source files carry zero prose comments under `scripts/check-comments.mjs`.

## Decisions

### 1. Autonomy Modes, Project Board, and Routines (`autonomy*`, `board-cli.ts`, `routine-*`)
- **Fail-closed autonomy resolution (`autonomy.ts`, `autonomy-cli.ts`)**: `autonomyOf` returns `"autonomous"` only when `value.autonomy === "autonomous"`; missing, null, or unrecognized values fail closed to `"supervised"`. `enrollmentAutonomy` passes any defined saved value through `autonomyOf` (a corrupted saved value becomes `"supervised"` with source `"saved"`, never falling through to host defaults), falling back to `config.autonomy.defaultMode ?? "autonomous"` only when `saved.autonomy === undefined`. `autonomy-cli.ts` validates mode, project ID, UUID `requestId`, and `--revision` before making any HTTP call, and prints the saved state on rerun after a lost reply when the saved mode already matches instead of sending a conflicting revision.
- **Routine constraints and wake deferral (`routine-types.ts`, `routine-cli.ts`)**: `routineGoalSchema` strips `requestId` and `standing` under `strict` validation so routines never start standing goals. `wakeOnSchema` omits a default so absent keys stay absent; `wakeOn` is fixed at approval. When a busy project refuses a wake start, `wakeDeferred` defers the pending wake until `nextRunAt`. `routine-cli.ts` logs `requestId` to `stderr` before issuing the POST so interrupted requests can be retried with the same identity.
- **Board grouping (`board-cli.ts`)**: A group holds a host project when `projectId` matches any repository's primary `projectId` or any nested checkout's `projectId`. `projectsLines` prints groups (repos and checkouts), hidden groups, then suggestions.

### 2. Delivery Lineage, Workspace Isolation, Publication, Retention, and Retirement (`delivery-review.ts`, `team-workspace.ts`, `team-changes.ts`, `team-publisher.ts`, `team-retention.ts`, `team-retirement.ts`, `team-recovery.ts`, `team-review-feedback.ts`, `team-kernel.ts`)
- **Delivery review lineage and policy pinning (`delivery-review.ts`)**: `assertReviewedDelivery` blocks publication if the configured delivery policy digest differs from the run's pinned `run.delivery`. `advanceDeliveryReviewLineage` extends contributor-family attribution only from the exact prior `headCommit`; any missing or mismatched lineage marks `unknown: true` and stays unprovable. `workspaceContributorFamilies` collects all implementer/integrator attempts from a shared workspace; `potentialRecoveryContributorFamilies` and `includeDeliveryReviewContributors` conservatively add prior-revision writers before a recovery PM can copy code; `rebaseDeliveryReviewLineage` and `inheritDeliveryReviewLineage` preserve lineage only across exact head continuity.
- **Workspace commands, Git hardening, and leader-exit drain (`team-workspace.ts`, `team-changes.ts`)**: `teamCommandEnvironment` exports only a fixed env allowlist plus `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL=/dev/null`, `hostEgressEnvironment()`, and optional per-operation GitHub grant; `teamGitEnvironment` forces `GIT_NO_REPLACE_OBJECTS=1` after `extra` so planted replace refs cannot falsify Git reads; `teamGitArgs` disables hooks, fsmonitor, and GPG signing. Commands end with their leader. A stop before leader exit has two sequences (INF-85): without a command prefix it `SIGKILL`s the leader's process group at once; under a prefix it sends `SIGTERM` to the group and, after `STOP_GRACE_MS` (5s), `SIGKILL` only while the leader still runs, because `sudo` relays the signals it can catch and cannot relay `SIGKILL` (measured with sudo 1.9.15p5 without a terminal: the relay reaches only the command's first process). An EPERM is recorded as a note rather than claimed as a stop. Setup and check commands run through `teamOperationCommand`, which passes `STOP_SETTLE_MS` (10s) as the stop bound and fails the operation with `command-stop-unconfirmed` when the bound passes, and under a prefix after every stop, since neither a delivered signal nor closed output proves that a prefixed command ended. The failed operation stays pending with its witness: the host runs nothing more for the run (Git, setup, checks, members, removal), and resume, steer and halt releases answer `team-command-running` (a mission's release: `team-operation-running`) until a witness census reports `ended`, or reports `unknown` and the owner has stated that the processes ended (`POST /api/teams/:id/processes-ended`, owner only, idempotent by request ID). The census runs outside the run's queue, single-flight per pending operation, and is applied only while that operation is still pending. The operation is cleared only in the step that accepts the resume, steer or release, and a restart keeps the failure and its reason. A process that survives the stop is fenced, not killed (follow-up INF-428); after leader exit without prior stop, pipes drain for at most `EXIT_DRAIN_MS` (1s) and `EXIT_DRAIN_TURNS` (3 loop turns) before abandoning open pipes and marking `leftover` + `truncated` without signaling the possibly-reused PGID. `captureMemberResult` verifies scope, stages the disposable copy, and creates one host-owned commit via `write-tree` + `commit-tree` (avoiding provider hooks and folding child commits); failed cherry-picks preserve the isolated conflict without reset or retry. Removal (`removeTeamWorkspace`, `removeMemberWorkspace`) requires `configuredRoot`, validates symlink-free host-owned roots (`chmodDirectoryNoFollow` via `O_NOFOLLOW`), runs agent-prefix `rm -rf` for agent-owned entries first, and lets the host finish host-owned entries (member scratch directories `0o2770` under `0o2750` host-owned parents). `changeIndex` parses NUL-delimited `--name-status -z -M` and `--numstat -z -M` (where renames emit an empty path field followed by two NUL fields).
- **Head publication, PR continuation, and GitHub review intake (`team-publisher.ts`, `team-kernel.ts`, `team-recovery.ts`, `team-review-feedback.ts`)**: Review and delivery wait behind `publicationGate` until `headCommit` is published (retrying on failure rather than blocking; pushing an immutable commit only reads objects and may overlap queued workspace ops). A run steered after delivery (`pullRequest.revision !== run.revision`) pushes intermediate heads to checkpoint branch `${runBranch}-${commit.slice(0, 8)}` under per-ref GitHub proxy grants and never moves the PR branch until delivery passes checks and independent review; `publishTeamHead` classifies divergence strictly on Git's `! [rejected] ... (non-fast-forward|fetch first)` ref status line. `TeamReviewFeedback` reads PRs via `gh pr view` under a read-only `pr` grant, saves a durable intent before steering so crash recovery checks the run's steer receipt first (preventing duplicate steers), coalesces concurrent requests into at most one running pass plus one `next` pass, bounds abort settle at `READ_SETTLE_MS = 5_000`, and logs only error kinds so review text never reaches logs.
- **Retention, operation witness census, and process-tree retirement (`team-retention.ts`, `team-recovery.ts`, `team-retirement.ts`)**: `TeamRetention` runs workspace removal and deduplicated unfinished-member snapshots (`memberWorkGroups`) outside the per-run serial queue, keeps `workspaceRemovedAt` and member removal markers durable on partial failure (`REMOVAL_RETRY_MS = 5 min`; trace cleanup uses `TraceRemovalError`), waits up to `EVIDENCE_WAIT_MS` (24h) for unblocked outbox projectors before removing records (`deleteRun` never throws), skips runs retained by live goals/missions/handoffs, and lifts a witnessed pending-operation fence only when a witness census reports `ended`, or `unknown` with the owner's statement recorded on the operation (zero matching or directory-using processes; terminal runs never replay interrupted ops): for automatic retention of a blocked or cancelled run, and for owner `removeRun` of any run that holds a pending operation with a witness. A command that exits while a process it started holds its output (`noteLeftover`) gives the run `Stored.leftover` (`since`, the operation id, a copy of the operation's witness merged again when the operation ends, and `census`, a union on `state`: `running` with `recorded`, `in-use` with `using`, `unknown` with `detail`); no later operation clears it. Every removal of the run's directories (retention of any settled status, owner `removeRun`) waits until a census reports `ended`, which clears it; with a pending witness too, one census of both witnesses decides each removal inside the run's queue. An active run that holds a leftover keeps its integrated member clones and takes no census for it. `unknown` lifts only on the owner's statement (`teamRemovalSchema`, `{ processesEnded: true }`), accepted only when the census taken for that request reports `unknown` and recorded as an event that names its detail. By contrast, operator-attested `TeamRecovery.reconcileVerification` skips the census when no witness exists and, with a witness, refuses `running` and `in-use` while permitting `unknown` under operator attestation (it restores the entire run snapshot on synchronous delivery-prep failures). `membersSettled` checks `manager.meta` existence before `state()` (deleted sessions can still return cached status files) and holds `halt === "cancel"` runs until active members record their stop. `team-retirement.ts` checkpoints newly discovered `(pid, born)` identities before signaling and freezes parents before children with `SIGSTOP` before issuing `SIGKILL` so no handler can fork an unobserved survivor.

### 3. Permission Agent: Policy, Shell/Class/Raise Rules, Core, Pipeline, Delegation, Delivery, and Headless Channel (`permission*`, `permissions-cli.ts`, `team-permission*`)
- **Fixed policy, delegation authority, onboarding, and write fencing (`permission-policy.ts`, `permission-agent-config.ts`, `permission-families.ts`, `permission-delegation.ts`, `permission-delegation-types.ts`, `permission-onboarding.ts`, `permission-write-fence.ts`)**: Host rules never allow a request; they only classify (`INTERRUPT_CLASSES`), qualify, lock, replay, or raise to the strong tier. `interruptClassesInForce` unions current host classes with pinned delegation classes so upgrades may add classes but never drop pinned ones. `requesterNotice` sends only fixed host strings (never model notes). `PermissionDelegationService` is single-writer, pins each covered project's root `path` and group `moveMark` (owner regroupings bump `moveMark` atomically without waiting on delegation writes), retains opt-outs, revocations, and `knownProjectIds` across unenroll/reenroll, refuses ambiguous workspace grants while revoking all matches (including absent unenrolled entries), sets `uncertain` on write failure to force disk reload before any further read/write, and covers during `repo init` (`onboardingPermissions`) only on a project's first enrollment (recording explicit `--permissions off` opt-outs *before* writing enrollment so a crash cannot leave a project covered). `protectedInstallPath` protects a marked release's container directory (`.infinite-release.json`) unless directly below `/`. `familyOf` resolves vendor families strictly without guessing (`undefined` on provider/model mismatch or unknown multi-vendor model). `permissionWriteFence` settles in-flight delivery fences before sending JSON on every non-read API route, annotating `deliveryFence: "uncertain"` when unconfirmed.
- **Conservative shell reading, real paths, and class/raise rules (`permission-shell.ts`, `permission-classes.ts`)**: `readShell` never runs commands; it reads literal shell bodies up to `MAX_SHELL_DEPTH = 3`, strips known `WRAPPERS` (tracking `chdir`, `root`, `split`, `writes`, and `privileged`), updates working directory on literal `cd`/`pushd` (marking unestablished directories `cwdUnknown`), flags code-injecting environment assignments (including `+=` appends, non-inert `NODE_OPTIONS`, dynamic-linker/startup hooks, `GIT_*`, non-inert pagers/editors, and non-relative `NODE_PATH`/`PYTHONPATH`/`GIT_DIR`), detects getopt-style interpreter inline code, piped/here-string `code-from-input`, GNU `sed` `e`, `git -c` command configs, PowerShell command flags, and remote `scp`/`rsync`/`sftp` operands. Live requests resolve roots (`withRealRoots`) and operands through `realHostPath` (`realpathSync.native` preserves `..` after symlink dereference and follows dangling symlinks; `~` stays symbolic and never counts as inside session; `/dev/{null,zero,...}` device paths are judged as written). `CLASS_RULES_VERSION` and `PERMISSION_CLASS_LISTS` feed `classRulesDigest` (invalidating replay readiness on change); because `classRulesDigest` hashes only the version, lists, and configured facts (not implementation code), maintainers **must** bump `CLASS_RULES_VERSION` whenever classifier or shell-reader logic changes so replays measured against old behavior are not treated as current. `runsPattern` skips `valuedGlobalOptions` strictly for class rules and skips unknown option values only in `loose` raise mode (`raise:option-subcommand`); `embeddedCommand` searches command tails and whitespace-containing arguments within `EMBEDDED_COMMAND_LIMITS` (`words: 64, length: 4000, readings: 256, layers: 2`) only to raise (`raise:embedded-command` or `raise:opaque`, never classifying directly). Wrapped multiline screen dialogs (`tool === "dialog"`, no `input`, `\n` in action) always raise (`raise:wrapped-dialog`).
- **Decision core, tool-less reviewer turns, and replay jobs (`permission-core.ts`, `permission-reviewer.ts`, `permission-replay.ts`, `permission-agent-routes.ts`, `permission-review-routes.ts`, `permission-control-routes.ts`, `permissions-cli.ts`)**: Fresh reviews run within `REVIEW_WINDOW_MS` (5 min) with `STRONG_ATTEMPTS = 2`, retrying with the next qualifying strong profile if available (reusing the sole qualifying profile when only one differs from the requester's family); raised or non-allowable requests skip the light tier (light tier can only `allow` or `refer`, never reject), and the strong tier requires a known requester family plus a different-family profile. `turnPrompt` frames untrusted request, task, reject, and file evidence inside per-turn random hex boundaries. `createCliTurnLauncher` runs Claude Code (print mode, zero built-in tools, init event verified to expose only `StructuredOutput` and zero MCP servers) or OpenCode (host-defined zero-tool agent verified via `openCodeToolsOff`) inside fresh `0o755` empty temp directories with sanitized `reviewerEnvironment` (retaining egress proxy settings) and re-checks the halt/launch gate immediately before spawn; Codex is excluded because `codex exec` still exposes execution/collaboration tools with feature flags disabled. `PermissionReplayJobs` runs one replay at a time against `permissionBinding` (policy + tier texts + classes + `classRulesDigest` + profiles) using in-case virtual `sources` (zero disk reads), computes 95% Wilson intervals (`DEFAULT_MAX_MISS_RATE = 0.05`, `DEFAULT_MIN_CASES = 100`), writes only to `permission-measurements`, and requires `requireOwnerCli`; `GET /api/permissions/log` is owner-only because entries include model notes; owner marks never alter decisions or locks.
- **Pipeline precedence, authority invalidation, and owner controls (`permission-pipeline.ts`)**: `decideFresh` enforces strict order: (1) coverage and halt check (unreadable halt counts as halted), (2) class rules, (3) qualify (`oneShotReject` required to review; `canAllow` requires qualified + `oneShotAccept`), (4) assignment lock (`REPEATS_BEFORE_LOCK = 2` open repeats), (5) replay (`latestReplayable` stops at the newest verdict — an `owner` or `host:read-source` verdict prevents falling back to older verdicts; replays never grant `allow` when `!canAllow`), (6) raise rules plus `hasRejectHistory`, (7) model review and strict validation (invalid reports become `unavailable`). `inForce` folds `core.binding` and `haltEpoch` into `authorityHash` so any policy, rule, profile, delegation, direction, or halt change invalidates prior verdicts and reuse keys. Decisions append to the journal before writing the pipeline authority row so an unrecorded authority row is never applicable; `host:read-source` allows cannot be replayed or re-delivered on retry; `requestDigestFor` keys interactive dialogs by `(sessionId, promptId)` across hook-evidence updates so repeats count once; `closeRejectsOnDirectionChange` closes open rejects only for projects covered both before and after a direction update.
- **Interactive delivery, team adapters, and coordinator-to-agent switch (`permission-delivery.ts`, `team-permissions.ts`, `team-permission-adapter.ts`, `team-permission-agent.ts`, `team-permission-evidence.ts`, `team-permission-review.ts`, `team-permission-recovery.ts`)**: `PermissionDeliveryService` writes durable `"intent"` to both its SQLite ledger (`permission-delivery`) and the journal *before* sending any key, inserts into `delivering`/`unknown` with no `await` after the authority check so owner writes fence in-flight sends, and never repeats an uncertain delivery; afterward, `record(kind)` swallows journal errors, so a confirmed refusal clears `unknown` (permitting retry after restart) as soon as the **ledger** write succeeds even if the journal still ends at `"intent"`, and only `refusedBeforeSend` confirms zero keys were sent. `teamPermissionAssignment` unifies the assignment seat key (`team:<runId>:<role>[:task:<taskId>]`) across interactive, headless, and replacement members. `TeamPermissionAgent` switches runs from legacy coordinator review to the permission agent via a fenced transition (`agentSwitched`): once `agentEligible`, coordinator reviews are retired and `unfencedAnswers` must settle/fence before `agentServes` activates. Collapsed Codex dialogs (`isCollapsedPermissionPrompt`) get at most one guarded display expansion (`AGENT_EXPANSION_SETTLE_MS = 5s`); dialogs lacking a one-shot accept wait `AGENT_EVIDENCE_SETTLE_MS = 1.5s` for hook evidence. `collectPermissionEvidence` refuses shell composition/newlines (visual wraps cannot be distinguished from command newlines) and resolves `.ts`/`.tsx` sources behind ESM `.js` specifiers.
- **Headless permission channel (`permission-headless.ts`, `permission-headless-worker.ts`, `permission-hook.ts`)**: Headless Claude Code sessions forward `PreToolUse` (`check`) and `PermissionRequest` (`request`) hooks via `permission-hook.ts` (using raw `node:http` because Node's `fetch` times out response headers at 5 min < 345s `RELAY_DEADLINE_MS`; relay deadlines 15s/345s stay below hook timeouts and above 10s/335s socket timeouts) through the worker's loopback server to the host's `0o600` Unix socket `permission-channel.sock`, authenticated by per-session HMAC `channelToken` and stateless `deliveryKey`. Class-matched primary-agent `PreToolUse` calls with `tool_use_id` defer the run (`DEFERRAL_RETENTION_MS = 29d` < provider 30d limit), open a `"protocol"` owner prompt (excluded from delegated screen/hook review), deny concurrent calls with `PENDING_NOTICE` (unlogged in permission journal), consume the owner's answer once before asking `op: "resume"` (which re-verifies `sessionRoot`, live run status, halt state, and — when the worker supplies `call` — `pipeline.applicable` against the rebuilt request; pre-upgrade workers surviving a host upgrade may omit `call`, in which case authority is checked without re-reading the current task or path interpretation), and block ordinary session resume via `deferredCallOpen` while an unreturned deferral exists. `PermissionRequest` hooks cannot defer (owner outcomes return `needs-owner`). Uncorrelated requests without `tool_use_id` match open `PreToolUse` calls via `recent` up to `OPEN_CALL_KEYS = 4096`, clearing and setting `lost = true` permanently on overflow or provider exit so stale hooks from an exited provider cannot match a resumed provider's calls.

### 4. Intent Checks, Verdicts, Register Passes, Goals, and Check Output Scanning (`intent-*`, `team-intent.ts`, `verdict-*`, `team-verdicts.ts`, `team-register.ts`, `goal-*`, `team-check-output.ts`, `team-acceptance.ts`, `team-goal-criteria.ts`, `team-planning.ts`, `teams.ts`)
- **Intent checks (`intent-prompt.ts`, `intent-report.ts`, `team-intent.ts`)**: `intentCheckerPrompt` is fixed text accepting no run data; `intentContext` strips log, `latest`, `proposals`, member-origin assumptions, and routing, returning `undefined` above `INTENT_CONTEXT_BYTES`. `TeamIntent` runs only when `run.intentCheck === "on"`, probes log room with an empty `PROBE_REPORT` and enforces `DECISION_LIMIT = 40` before holding, allows at most 1 replacement checker before skipping and accepting the held plan, checks read-only working copy before applying (aborted checks do not count as failures), and records owner answers as directions while delegate answers only release waits; `release` / `releaseWaits` never throw.
- **Verdicts and register passes (`verdict-compose.ts`, `verdict-prompt.ts`, `verdict-store.ts`, `verdict-types.ts`, `verdict-view.ts`, `team-verdicts.ts`, `team-register.ts`)**: `evaluatorPrompt` takes no run data; `verdictContext` exposes only owner text, active criteria, head-matched `changedPaths` (marked `truncated: true` if head differs), final check round names/statuses (never output; `finalCheckRound` includes setup rows so a round with only a failed setup passed nothing), and head-matched receipts, refusing over `VERDICT_CONTEXT_BYTES` (`context-too-large`). Composition enforces three rules: (1) any changed pinned file (or truncated change list) downgrades `met` to `inconclusive` (`pinned-changed`), (2) host-produced criterion states stand while opposite evaluator verdicts set `contradicted: true` (evaluator `inconclusive` is not a contradiction), (3) empty criteria lists are never `met`. `verdictRecord` returns `"log-full"` past `VERDICT_LOG` (300 entries / 160 KiB) and never writes notes. `TeamVerdicts` drives `testing` (waiting up to `VERDICT_TESTING_WAIT_MS = 300s` for `TeamRegister.markReviewed`) → `queued` → `evaluating` (verifying criterion statement+check `judged` SHA-256 digests and read-only workspace, at most 1 replacement, never stopping a run at `memberLimit`) → `releasing` (no-change) → `done`; for no-change goal cycles, evaluator independence includes parent-run members, and `cycleOf` collects every implementer/integrator/reviewer/PM across all revisions because edits can survive steer/resume. On goal verdicts, `TeamVerdicts` writes the goal's objective record before saving the run assessment and outbox event: a restart between those two saves can legitimately leave `verdict.recorded` on the goal without a run assessment, and recovery deduplicates by handle `verdict:<id>` rather than appending the verdict twice or inventing an assessment. `verdict-store.ts` records only IDs/enums/counts (no text), stamps `v: 1`, stamps `deleteRun` without deleting, skips malformed events without blocking projection, and sweeps expired rows without throwing. `TeamRegister` plans in queue, reads blobs outside queue (120s deadline, max 4 stalled reads), applies receipts in queue, and never lets `mark`/`drain`/`propose` throw.
- **Goal digests, metrics, standing goals, and goal verdicts (`goal-digest.ts`, `goal-metrics.ts`, `goal-standing.ts`, `goal-verdicts.ts`)**: `goal-digest.ts` is pure, total, and linear-time within `GOAL_DIGEST_LIMIT_BYTES = 8192`, fitting three authority tiers in order — receipts (fitted alone with widest-counter/marker reserve so claims/history never evict receipts), claims (`decisions`/`open`/`criteria` from the last cycle only), and history — refusing invalid fixed fields without throwing, returning `previous` refitted when `ended.cycle <= previous.cycle` (idempotent replay), carrying failures only when `reviewedHead === undefined`, and taking `outsideContent`/`unclearedHead` solely from the latest input. `goalDigestSchema` and `fitGoalDigest()` check only shape and size and never authenticate a `by: "receipt"` label: callers **must** supply `previous` and `ended` exclusively from host-owned records rather than member-supplied JSON. `goal-metrics.ts` stores `CycleMetrics` beside `goal` on the holder (excluded from goal views and member context), preserves unrecognized future shapes across rollbacks (`isGoalMetrics`), keeps 16 values/cycle, prunes to 50 entries in cycle order (counting retention drops in `dropped`), and derives up to 8 series dynamically on read. `goal-standing.ts` classifies cycle outcomes (only `ready-for-review`/`merged` heads become next-cycle parents; owner stops and fuse-open timeouts are `excluded`), blocks next cycles on unresolved external operations (`unresolvedOperation`), fits wakes within `runObjectiveLimitBytes = 24000` without truncating the owner's objective (dropping receipts first), restores withdrawn launch wakes ahead of newer signals, and enumerates transient creation failures (`retryableCreation`). `goal-verdicts.ts` triggers `provisional-met` stops only on pinned-autonomous finite goals with a current reviewed `met` verdict, clears `provisional-met` on owner outcome, and passes active `criteriaRowsFor` to the next cycle only when prompts, evaluator, and autonomous mode are all enabled.
- **Check output scanning and plan validation (`team-check-output.ts`, `team-acceptance.ts`, `team-goal-criteria.ts`, `team-planning.ts`, `teams.ts`)**: `CheckOutputScanner` scans stdout/stderr in bounded memory (`PENDING_BYTES = 4096` prefix, `MAX_DISTINCT = 1024` SHA-256 marker hashes over full raw line minus leading whitespace, `KEEP_FAILURES = 8`, `DETAIL_LINES = 30`, `DETAIL_BYTES = 1500`, `FEEDBACK_BYTES = 12000` with `END_RESERVE_BYTES = 2000`), matches TAP `# skip`/`# todo` directives in constant streaming state over arbitrarily long lines, re-cleans stored scans so output lines stay prefixed with `| `, and shows only the first non-passing check inline. `validateGoalTaskCriterionRefs` validates task-to-criterion links only when the PM prompt carries a goal-record pin (`goalPlanCorrectionRevision` allows one correction per revision).

### 5. Blind Judges, Calibration Jobs, and Replay Runs (`judge-*`, `duel-cli.ts`, `team-replay.ts`)
- **Blind package, prompt, and eval isolation (`judge-package.ts`, `judge-prompt.ts`, `judge-types.ts`, `team-replay.ts`)**: `judgePrompt` takes only `provider` (no run, profile, or duel ID); `judgeTaskOf` and `judgeContext` strip task IDs, contestants, profiles, and member IDs; `writeJudgePackage` writes `A.patch`, `B.patch`, `task.json`, and `gate.json` under `.git/infinite-judge` (never in the working tree) with deterministic `labelDraw` (`sha256(seed)[0] & 1`). `TeamReplay` executes replay/duel commands through the eval launcher (`exec` / `setup` passing `_eval-setup` proxy URL via stdin), verifies `canonicalRoot()` for non-group/world-writable eval-owned directories beneath host-owned ancestors, accepts judge reports strictly on matching `duelId` within `judgeMinutes` with an unchanged working copy (no fallbacks/replacements), and shields `purpose === "duel"` runs from generic `TeamService` stepping via `judgeStep`.
- **Calibration scoring, scheduling, and storage (`judge-calibration-rules.ts`, `judge-calibration-jobs.ts`, `judge-store.ts`, `judge-routes.ts`, `duel-cli.ts`)**: Each calibration pair runs in both label orders; a pair is `pairCorrect` only when both orderings prefer the resolved trial and `pairAgrees` only when both prefer the same non-tie trial; lower confidence uses the Wilson score interval (`WILSON_Z = 1.96`, `CALIBRATION_MIN_PAIRS = 30`, `CALIBRATION_VALID_DAYS = 60`); Phase-2 admission weight is `max(0, 2 * accuracy - 1)`. Selection pulls round-robin across eval-configured projects excluding pairs whose recorded trial profile matches the judge's `(provider, model)`, then regroups kept pairs by project so the grader streams each project's bundle once (`graderJobOf` isolates bundles per project). Deterministic v4-shaped UUIDs (`stableUuid`) make `begin`/`finish` idempotent; a dropped ordering or 3 void attempts ends the pair immediately; `release` absorbs up to `CALIBRATION_RELEASES = 10` consecutive pre-session failures before voiding the attempt so one bad pair cannot stall a job; early completion sets `not-ok` (`pairs-dropped`) as soon as `counted + pending < 30`. `judge-store.ts` seals all task/trial/profile IDs and rubrics, retains `session_id` until `clearJudgementSession` records cost once, exposes only counts/rates/known-spend floor (`duel-cli.ts` prints unmeasured values as `unknown`, never `0`), gates calibration start/cancel behind `owner` (views behind `read`), and sweeps expired rows in bounded batches.

### 6. Team Prompts, MCP Transport, Entries, Mission Progress, Usage Rollups, List Views, and Watch UI (`team-prompts.ts`, `team-rule-texts.ts`, `team-mcp*.ts`, `team-entry*.ts`, `team-report*.ts`, `mission-progress.ts`, `mission-read-routes.ts`, `team-usage.ts`, `team-list.ts`, `team-watch.ts`)
- **Prompts, retargeting, and mission budgets (`team-prompts.ts`, `team-rule-texts.ts`)**: `teamContext` is written to `.git/infinite-team-context.json`, strips private project settings (`withoutPrivateSettings`), excludes `permission-coordinator`/`evaluator`/`judge` from PM reports (`UNREPORTED_ROLES`), strips `routing` (`withoutRouting`), and omits `goal.successCriteria` when a pinned record digest carries `c0`. `retargetPrompt` and `refreshReportingInstructions` replace only recognized host paragraphs matched by exact text (`KNOWN_RULE_TEXTS` is append-only): when anchors are missing, `retargetPrompt` returns `undefined` so a member never launches with another provider's reporting instructions, whereas `refreshReportingInstructions` returns the original prompt unchanged (so a successful refresh does not certify cross-provider safety). Mission prompts (`missionPromptWithMessageCount`) stay within `MISSION_PROMPT_LIMIT_BYTES` (80 KiB), list only newly delivered direction messages, include all open owner decisions plus the last 20 answered ones, and give coordinator `notes` only leftover bytes after the leading message fits whole.
- **MCP transport, reports, and blackboard entries (`team-mcp.ts`, `team-mcp-results.ts`, `team-report-client.ts`, `team-report.ts`, `team-entry*.ts`)**: `runTeamMcp` uses newline-delimited JSON-RPC awaiting each frame for stdin backpressure, never executes tools on notifications (`id === undefined`), validates every tool answer against strict Zod `outputSchemas` checked at compile time via `Exact<A, B>` without echoing raw answers on mismatch, and preserves worker key order on read answers. `team-report-client.ts` derives deterministic UUIDv8 `requestId` from canonical `(assignment, report[, note])` for idempotent retries; HTTP 204 returns only after durable worker journal append, and transport errors report unconfirmed (not failed). `team-entry-route.ts` enforces per-attempt caps inside closure state without counting refused calls and enforces supersede scope (same kind, own or same task). `team-entry-ingest.ts` ingests up to `ENTRY_INGEST_MEMBERS = 16` members × `ENTRY_INGEST_PAGE = 200` events per 1s pass via round-robin `EntryIngestQueue` without copying the whole queue, advances cursors only after `Blackboard.ingest` stores the page (never throwing; `kept` hooks cannot roll back a stored page), and marks stopped/reported members done once drained.
- **Mission progress, list views, usage rollups, and watch UI (`mission-progress.ts`, `mission-read-routes.ts`, `team-usage.ts`, `team-list.ts`, `team-watch.ts`)**: `MissionProgressService` samples read-only snapshots on request behind paired-device auth, coalesces concurrent reads per mission (`inFlight`), caps host-wide worker socket reads without queuing (reporting unsampled liveness instead), prioritizes active assignments under row/byte caps, keeps `recordedStatus` separate from live `workerStatus`, omits source `updatedAt` in favor of `observedAt`, and replays only distinct snapshots observed by this process generation. `teamListItem` keeps every field needed by web/phone/Mac list views (including check command/phase and task `dependsOn`, capping changed paths at `LIST_CHANGED_PATHS = 20` and events to the latest entry) while dropping long detail fields. `teamUsage` computes rollups on read (never stored in sealed run records), distinguishes `unmeasuredMembers` (unknown cost, never `0`) from `partialMembers` (defaulting legacy missing `partialMembers` to `0`), and aggregates multi-session members by `(runId, memberId)`. `team-watch.ts` keeps the last written brief visible on refresh failure, omits relative timestamps when printing only on change, keeps fixed terminal screen height without trimming blank rows, and pins the footer key bar without scrolling past the last terminal row.
