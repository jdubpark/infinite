# ADR-0021: Host Core Runtime, Transports, Boundaries, Telemetry, and Integrations Invariants

- **Status**: Accepted
- **Scope**: `packages/host/src/` (140 core host runtime, transport, security boundary, fuse, signal, telemetry, integration, memory, understanding, search/read-pool, digest, and workspace sync modules)

## Context

Beyond the orchestration, eval/evidence/outcome/routing, and core manager/types modules documented in earlier ADRs, the remaining 140 source modules in `packages/host/src/` encode non-obvious HTTP/WebSocket transport rules, fail-closed security boundaries, OS process accounting, transcript/usage reconciliation, external tracker rate-limit and idempotency contracts, encrypted memory recovery, pure search/read-pool state machines, and workspace sync durability invariants. Their rationale was previously spread across 1,794 inline comment blocks (3,286 comment lines). This ADR consolidates every non-obvious architectural, security, concurrency, protocol, and compatibility decision so all 140 files carry zero prose comments under `scripts/check-comments.mjs`.

## Decisions

### 1. HTTP Server, Live Streams, Session Listings, and Remote Access (`server.ts`, `remote-access.ts`, `relay.ts`, `live.ts`, `session-list.ts`, `session-listing.ts`, `session-content.ts`, `machine.ts`, `machine-cli.ts`, `device-control.ts`, `decision-queue.ts`, `decision-queue-read.ts`, `ipc.ts`, `failure-reason.ts`, `halt-cli.ts`, `signal-cli.ts`)
- **Startup and middleware ordering (`server.ts`)**: `EvidenceStore` registers `configurationModule` before its projector and fails soft (`unavailable`) without blocking runs or removals. `FuseService` starts before any service that consumes it and stops before the store closes. `outcomeBackfill` runs its first synchronous pass before any timer can fire so partial history is never served. `HaltService` sits ahead of both `FuseService` and `permissionTurnGate` so halted launches never burn fuse allowance and host halts hold reviewer/replay turns. Every `/api` write passes through `permissionWriteFence(settlePermissionAuthority)` before sending JSON so the response waits for the fencing attempt across revoked/changed delegations, opt-outs, regroupings, and halts (`deliveryFence: "uncertain"` is included in the JSON reply when worker confirmation fails, and keys already transmitted cannot be recalled). `refuseMissionManaged` attaches after route matching and before role checks using Express's decoded route params so casing, escapes, or trailing slashes cannot bypass the mission boundary. `server.once("listening", ...)` consolidates subsystem startup into one listener to stay under Node's emitter limit.
- **Admission and sync concurrency fences (`server.ts`)**: `startsInFlight` and `projectConfigChanges` close async gaps between session listings and project mutations. `sessionRunningInProject` counts only work touching the project tree itself (excluding team clones and laptop-mode tools) and fails closed if session listing fails or lacks a directory. `projectRunning` runs only after `applying()` turns true so new starts either observe the flag or enter `startsInFlight` beforehand. `startGoal` replays existing `requestId` records before busy checks so an already-admitted goal does not block its own retry. `/api/projects/:id/sync` requires `single-tenant` tenancy because sync moves ignored files and credentials.
- **Error redaction and wire compatibility (`server.ts`, `failure-reason.ts`)**: Fixed-message handlers (`/api/outcomes/legacy` validation failure and the generic error fallback) redact filesystem paths, prompts, tokens, and malformed operator keys/values rather than echoing them back; general Zod validation responses may still report schema issue details such as rejected property names and should not be assumed redacted. `inputAuthority` preserves the pre-upgrade request shape for retained workers that hash the full request body. `machine.ts` derives an opaque stable host identity without exposing hostnames or paths; `machine-cli.ts` validates a prospective config in a temp file before replacing the active config and refuses unlinking a non-socket at the relay proxy path.
- **Untrusted relay and encrypted remote access (`relay.ts`, `remote-access.ts`, `device-control.ts`)**: `createRelayServer` routes only ciphertext and routing metadata, never consumes device keys, and never serves the dev web client. When `relay.proxy` is configured on a restricted Unix socket, client channels are accepted only through that proxy and rate-limited by IPv4 or IPv6 `/64` (60/min, evicting oldest buckets at `MAX_TRACKED_ADDRESSES` so rotating clients cannot lock out others; registered hosts bypass address throttling on valid auth). `remote-access.ts` rejects percent-encoded or normalized path tricks on its route allowlist, intentionally accepts browser `Origin` headers on `/api/remote` (no cookies or plaintext bearers are read; authentication completes only after a fresh encrypted request proves key possession so replayed hellos cannot pin sockets), polls device revocation every 1s for idle streams, bounds unfinished SSE tails separately from completed frames, and falls back to compact team rows for `TEAM_LIST_RETRY_MS` (5m) whenever a full `/api/teams` response exceeds the remote frame limit. `device-control.ts` binds leases to both the authenticated device key and a client instance ID rather than client labels.
- **Live feeds, versioned listings, and read caches (`live.ts`, `session-list.ts`, `session-listing.ts`, `session-content.ts`, `decision-queue.ts`, `decision-queue-read.ts`)**: `LiveFeed` latches a topic into `"refetch"` once an event exceeds `MAX_EVENTS_EVENT_BYTES` so later inline events cannot advance a phone's cursor past unfetched data, and resends unchanged session lists every `UNCHANGED_SESSIONS_RESEND_MS` (60s) so relative ages advance on quiet clients. `sendSessionList` hashes a single serialized payload into a 22-char (132-bit) SHA-256 base64url `version` for `since` checks. `SealedFileCache` skips caching files younger than `SETTLED_MS` (2s, newer of mtime/ctime) and drops all entries on clock step-back; `listedSavedState` uses recorded `savedAt` (never read time) so listings remain deterministic across polls and restarts. `sessionFile` resolves symlinks before containment checks and allocates `stat.size + 1` to enforce size caps against concurrent growth. `readDecisionQueue` invokes `Manager.observeListings` before collecting queue items so permission-agent-claimed dialogs never flash as owner decisions; `terminalOnly` rows remain visible in the queue while their `answerPath` refuses remote answers.

### 2. Client CLI, Native Provider Bridges, Terminal Snapshots, and Cmux (`client.ts`, `client-entry.ts`, `client-draft.ts`, `client-draft-store.ts`, `client-native.ts`, `client-opencode.ts`, `client-transport.ts`, `native-bridge.ts`, `native-codex.ts`, `native-continuation.ts`, `native-http.ts`, `native-opencode.ts`, `native-transport.ts`, `terminal-snapshot.ts`, `terminal-stream.ts`, `cmux/*`, `demo.ts`)
- **Client CLI and crash-safe drafts (`client.ts`, `client-entry.ts`, `client-draft.ts`, `client-draft-store.ts`, `client-transport.ts`)**: `client-entry.ts` routes `--laptop-service` and `--sync-service` IPC bootstraps past the interactive CLI parser. `client.ts` validates `PROJECT_ID` before forming local sync paths, leaves unknown server-admin commands and trailing options untouched, keeps `sync --stop`/`--status` strictly local/offline, compares enrolled checkouts with `GIT_NO_LAZY_FETCH=1` so partial clones never hit the network, refuses pulling an export into a directory owned by a sync service, suppresses device-query and clipboard OSC sequences during terminal replay, omits absent model/effort values (preserving OpenCode's literal `"none"` variant), and never formats missing outcome or usage values as `0`. `client-draft-store.ts` isolates one file per client instance and deletes a crashed client's original only after durable recovery; `client-draft.ts` writes `"uncertain"` to disk before transmitting bytes and mirrors cloud terminal redraws behind the local editor, prefixing `\x18` on restore to cancel partial escape sequences.
- **Native provider frontends and transport (`native-bridge.ts`, `client-native.ts`, `client-opencode.ts`, `native-codex.ts`, `native-continuation.ts`, `native-http.ts`, `native-opencode.ts`, `native-transport.ts`)**: `native-bridge.ts` restricts native protocol upgrades to owner keys (rejecting cookies and narrower roles), blocks human native attachment on mission-managed sessions before the owner check while preserving executor tunnel upgrades, and verifies the worker returned a loopback gate URL. `client-native.ts` and `client-opencode.ts` bridge cloud credentials through a short-lived loopback relay, finish the cloud handshake before launching Codex (whose initialize deadline starts on loopback connect), cut off provider transport before `SIGTERM` on detach so graceful TUI cleanup cannot abort a cloud turn, and explicitly disable mouse/focus/bracketed-paste/kitty terminal modes after `stty`. `native-codex.ts` keeps provider credentials inside the host process, pins `cwd` and workspace roots across `thread/resume` and `thread/settings/update` so Codex's sticky environment cannot reset to the host, restricts timeline recording to the single persistent observer, and drains child diagnostics without exposing paths. `native-opencode.ts` leaves `options: []` rather than inventing approval buttons from unverified dialog mappings. `native-http.ts` enforces a 15s handshake timeout while leaving streaming SSE unbounded. `native-transport.ts` sets a 32 MiB single-message bound (for startup catalogs), compresses only the cloud hop with independent per-message contexts, and lets subsequent turn events and approval requests overtake an in-flight chunked catalog read response (`plugin/list`) while preserving relative order among non-catalog frames.
- **Terminal snapshots and replay (`terminal-snapshot.ts`, `terminal-stream.ts`)**: `TerminalSnapshots` tracks parser states that xterm's serializer omits (saved cursors, tab stops, non-query OSC palette/hyperlink/default-color mutations that persist across RIS, extended underline styles/colors, mixed color SGR syntax) and forces full journal replay whenever any occurs; valid snapshots prepend `\x1bc` (RIS) so prior attachment modes never leak. `terminalPages` attaches the live watcher before capturing a snapshot so deltas begin strictly after the snapshot cursor, and falls back to lossless replay on unsupported state. `terminal-stream.ts` drains in-flight claims before releasing leases and stops refreshing fallback leases on managed sessions once `needs-you` closes.
- **Cmux adapter (`cmux/client.ts`, `cmux/discovery.ts`, `cmux/index.ts`, `cmux/prompts.ts`, `cmux/transcripts.ts`)**: `cmux/client.ts` invokes binaries without a shell and never auto-retries failed mutations. `foregroundAgent` checks the hook PID's process, foreground process group, expected non-shell provider executable, and TTY when available (checking `CMUX_SURFACE_ID` only during its launch-tag fallback when neither a hook PID nor a TTY is available); the host lease does not exclude local typing or other cmux controllers. `CmuxSessions` expires stale queued observations while preserving mutations, reads only the current viewport (omitting `lines` so scrollback dialogs cannot authorize input), ignores dim placeholder spans when detecting unfinished local input, keeps an existing native identity bound to its original project root, detaches `surfaceId` when a newer conversation takes over a surface, latches unanswered Feed approvals across outages, persists durable `"uncertain"` receipts before external paste/reply mutations (never retrying uncertain input), refuses raw control bytes (`terminal.paste` only), closes a whole workspace only when a fresh tree proves a single surface, degrades to `unavailable` with `control: null` on `cmux-busy`, and persists per-record changes independently so one save error does not lose other merged hook/Vault updates. `cmux/transcripts.ts` tracks line+block cursors and skips complete oversized JSONL lines without advancing past incomplete final appends.

### 3. Worker Runtime, Launch Isolation, Security Boundaries, and Process Control (`worker.ts`, `launch.ts`, `ceilings.ts`, `egress.ts`, `github-grants.ts`, `workspace-trust.ts`, `sudo-profile.ts`, `context-continuation.ts`, `code-mode.ts`, `cloud-executor.ts`, `deployment.ts`, `host-load.ts`, `storage.ts`, `fleet.ts`, `handoffs.ts`, `handoff-types.ts`, `handoff-processes.ts`, `process-census.ts`, `git-stream.ts`, `member-traces.ts`)
- **Worker lifecycle, journaling, and guarded prompt delivery (`worker.ts`)**: Bootstrap config arrives strictly over a private pipe. Every journal write goes through `append()`, which suspends the session (`recordingFailure`) on failure instead of losing audit history. `snapshot()` synchronizes xterm output with an empty write barrier (`terminal.write("", resolve)`) and re-checks `recording-error`. `issuedCredentials` tracks every session secret injected at launch (GitHub grant, egress password, observer token) so member blackboard entries containing any credential are rejected. Prompt answers (team and session permission-agent) re-verify the exact reviewed screen text (because prompt hashes ignore spacing inside lines) and bottom-pinned evidence synchronously before every key write, refuse `yes-no` dialogs for delegated answers (typing `y` mutates the screen before Enter), send Enter only once the selection marker lands on the target option, allow control and invalidation IPCs to fence between awaited terminal writes, and leave interrupted delegated receipts `"uncertain"` without re-pressing keys. Free text is allowed only after a recognized reject-with-feedback option once the dialog closes and no new dialog appears. On exit, the exit event journals before `finalDrain` so input gates close immediately; a deferred headless permission call keeps the session open across provider exit and resumes the conversation in place on owner answer.
- **Launch isolation, hooks, ceilings, and trust (`launch.ts`, `code-mode.ts`, `context-continuation.ts`, `ceilings.ts`, `workspace-trust.ts`, `sudo-profile.ts`)**: `DEFAULT_HOOKS` leaves Codex hooks off (`--dangerously-bypass-hook-trust` would allow untrusted working-directory hooks) while retaining turn-end `notify`. Non-channel Claude team launches pass `--setting-sources user` so `.claude/settings.json` or `.mcp.json` committed by another member never runs hooks or MCP servers; served headless Claude passes `--setting-sources ""` with `disableAllHooks: false` and keeps channel hooks separate from the signal relay (excluding `PermissionRequest` from signal relay so the relay never becomes a provider decision or prematurely pushes the owner). `missionCoordinatorLaunch` accepts only `MissionCoordinatorProvider` (`"claude"`), strips variadic tool flags before appending `--permission-mode dontAsk --tools Read,Glob,Grep` ahead of positional prompts, and fails closed at runtime; Codex team launches omit `INFINITE_MISSION_ASSIGNMENT` and `tools.mission_report.approval_mode` because Codex merges inherited MCP server tables (`-c mcp_servers={}` and profiles do not clear them) and `CODEX_HOME` isolation cannot preserve credentials safely across the `infinite-host`→`infinite-agent` `sudo` boundary (`missionLineupSchema`, `validateIntakeConfig`, and `MissionService.enabled()` reject non-Claude mission coordinators at schema and config parse time). `code-mode.ts` appends program rules at launch only (never stored in member prompts) and injects `CLAUDE_CODE_MODE_ENV` through `--settings` ahead of native arguments when sudo strips env vars. `context-continuation.ts` blocks conversation-selection flags/subcommands including dash-leading missing values and post-positional subcommands. `ceilings.ts` reads root-owned templates via `O_NOFOLLOW | O_NONBLOCK`, rejects placement before reading bytes if any ancestor is a symlink or non-root-writable, and uses an allowlist for Codex sandbox modes (`read-only`, `workspace-write`) and profiles (`:read-only`, `:workspace`) while flagging hidden aliases (`--yolo`, `-s=VALUE`). `workspace-trust.ts` refuses Codex launch when any `.codex` exists up to `.git` (`project_root_markers=[".git"]` pinned) and acquires Claude's `<file>.lock` directory lock (10s stale threshold) across read-modify-write. `sudo-profile.ts` allowlists sudo options strictly before `--` so a provider's `--` is never misread.
- **Stateless egress and GitHub credential boundaries (`egress.ts`, `github-grants.ts`, `cloud-executor.ts`, `deployment.ts`)**: `egress.ts` clears inherited proxy vars and mints stateless HMAC-SHA256 `v1.EXPIRES.MAC` credentials (`PROJECT.SESSION`, 30d session / 24h host, loopback direct; learning sessions use `_eval`/`_eval-setup`). If egress is configured but the shared 32-byte key is unreadable, commands and workers receive uncredentialed proxy variables (answered `407`) so host-account processes outside the agent firewall rule never fail open to direct network access. `github-grants.ts` mints `v2.<payload>.<mac>` grants (24h max / 15m host), validates refs against control/Git-special chars and `refs/*`, reads the grant key via `O_NOFOLLOW` descriptor checks below root-owned non-symlink ancestors, grants mission coordinators and permission reviewers none, limits delivery to the run's head branch (merge only under merge policy), and defaults non-team sessions to fetch-only unless the creation path explicitly vouches `owner-started`. `cloud-executor.ts` binds helper lifetime to an inherited parent pipe (noting process-group cleanup is not a fence for detached descendants).
- **Process census, handoffs, git streams, member traces, and host resources (`process-census.ts`, `handoffs.ts`, `handoff-types.ts`, `handoff-processes.ts`, `git-stream.ts`, `member-traces.ts`, `host-load.ts`, `storage.ts`, `fleet.ts`)**: `process-census.ts` pairs a boot-scoped `ProcessWitness` (4,096 cap with sticky `overflow`) with `directoryCensus` (a single directory scan; on Linux it checks `pid === 1` for `hidepid`, reads `/proc/<pid>/cwd` last to tell exited tasks from unreadable descriptors, rechecks unreadable tasks after `LOOK_AGAIN_MS = 100`, checks effective/saved/fs UID while ignoring real UID so setuid `sudo` is not misattributed; the `sudo -n` wrapper receives target path on stdin and its JSON output is strictly validated). `operationCensus` combines directory and witness findings and performs the two-pass confirmation (waiting after a clean first pass before scanning again) required by `main-check.ts`. Given earlier processes, each pass drops an `unreadable` finding through `excuseEarlier` only when the pid's current start token equals a recorded one (`"all"` drops every `unreadable` finding and nothing else); a token that cannot be read keeps the finding. `handoff-processes.ts` signals the group only while the leader matches and sends `SIGKILL` only to verified surviving identities; `HandoffService` persists transfer records before mutating source sessions and caches settled `metaRevision` entries. `git-stream.ts` enforces strict `maxBytes` without truncation, rejects Git revision syntax (`^ ~ { } @ -g<hex>`) in `COMMIT:PATH`, and counts EPERM-refused children as stalled until `close` (unreffing after `releaseMs`). `member-traces.ts` enforces post-exit Codex trace caps per manifest (marking `removing` before unlink and `removed` after, `O_NOFOLLOW | O_NONBLOCK` manifest reads, unlinking symlinks as themselves without following targets, `not-recorded` under sudo profiles, and acknowledging single-account caps are cooperative and Node lacks `openat`). `host-load.ts` uses Linux `MemAvailable` (falling back to free memory) and only overwrites host-load hold reasons; `storage.ts` computes fullness as the scarcer of bytes and inodes.
- **Process-group stops after the leader's exit (`process-group.ts`, `group-supervisor.ts`, `git-stream.ts`, the `server.ts` bundle pull, `repository-graphs.ts`, `understanding-runtime.ts`, `understanding-adapter.ts`, `repository-briefings.ts`, `cloud-executor.ts`, `laptop-service.ts`)**: A spawner that starts a detached child stops it with a signal to the child's process group, and once Node has reaped the leader and no process is left in the group, that group id is free for reuse. Spawners therefore signal through `signalGroup`, which signals only while the leader has neither `exitCode` nor `signalCode`. Node sets those codes when it runs the child's exit callback, not when it reaps the child: one pass reaps every exited child and then runs their callbacks, so inside one child's `exit` listener a sibling reaped in the same pass still shows both codes `null` while `kill(pid, 0)` already answers `ESRCH`, and a group signal sent to that sibling from there reaches any process left in its group. Each spawner except the two executor supervisors, which exit with their leader, also attaches `watchLeader`: when the leader exits but a process that left its group still holds the output, the watch waits `EXIT_DRAIN_MS` (the drain `teamCommand` uses, INF-393), then destroys the output streams so `close` fires, and the spawner reports the run as a failure because its output is not proven whole. A reader that has paused the stream (bundle backpressure) when the drain ends, or when the watch decides a turn later, re-arms the drain instead, and bytes still arriving hold the decision open for up to three loop turns. A stop that sends `SIGTERM` first would then miss a group member that ignores `SIGTERM` once the leader has ended on it, so the spawners that do (the graph build, the context read, the System tab brief, the session brief and the executor supervisors, which share `GROUP_SUPERVISOR`) start their command through `spawnGroup` or `supervisorArgs` behind `GROUP_ANCHOR`, a POSIX `/bin/sh` script that leads the group (INF-428). The anchor runs the command in the foreground with `SIGTERM` trapped. When the command ends after a `SIGTERM`, the anchor leaves a sleeper in the group that sends the group `SIGKILL` once the stop's grace, rounded up to whole seconds, has passed since the command ended, so the sleeper lives up to the grace plus the rounded grace after the stop and keeps the group id taken until then. It holds none of the caller's descriptors, so `close` does not wait for it, and `process-group.test.ts` requires `close` within half the grace. The anchor itself ends as the command ended, with its status or by raising its signal on itself, and its own messages go to `/dev/null`, so callers read the status, signal and output they read before, stops still end on `SIGTERM` without waiting for the grace, and `process-group.test.ts` compares a grouped spawn with a direct one. The command still sees four differences: its parent is the anchor, so it no longer leads its process group or session; `PWD` set to its cwd; an absolute `argv[0]`; and, where `/bin/sh` is bash, `SHLVL`. The sleeper carries that environment and cwd, and its argv, the anchor's, holds the command's path and arguments, so a directory census sees it by cwd or argv as it would see the running command. In a team run directory, a stopped member session brief (`repository-briefings.ts`, grace 3 s) or work narrative (`understanding-work-narrative.ts` through the adapter, 500 ms rounded to 1 s) therefore stays visible for up to its rounded grace after its command ends, and a forced verification reconcile in that window may return 409 (`team-recovery.ts`). For a blocked run with an interrupted operation, a retention census (`TeamRetention.retire`) that catches the sleeper records an event and caches `in-use` for `CENSUS_TTL_MS`, 10 minutes (`teams.ts`), and the run's workspace removal waits up to that long, because it needs a census that answers `ended` (`team-retention.ts`). A command that ignores `SIGTERM` keeps the anchor waiting, so the host's `SIGKILL` after the grace (`terminateGroup`, or the supervisor's timer) still reaches the group. A command that is not an executable file on the child's `PATH` is spawned without the anchor, so it still raises `error`. `spawnGroup` refuses a fourth stdio entry and an `ipc` entry, because the anchor keeps the caller's stderr on descriptor 3. The Git stream reads and the bundle pull stop with an immediate group `SIGKILL` while the leader runs and stay without an anchor. Limits: nothing sweeps the group when the command exits on its own, so a process it leaves in the group outlives it (INF-499); an exit status above 128 that names a signal, such as `exit 129`, reaches callers as that signal; Windows spawns are unchanged; the anchor is verified under Linux dash and `bash --posix`, not under macOS `/bin/sh`; and the anchor's `ulimit -c 0`, which keeps a raised core signal from dumping the shell, is the one command outside POSIX. If the host dies between a stop's `SIGTERM` and its `SIGKILL`, the sleeper still ends the group of a command that obeyed `SIGTERM`, but a command that ignores `SIGTERM` survives with its anchor and its whole group: the sleeper starts only when the command ends, and the `SIGKILL` timer (`terminateGroup`, or the place's own timer) and the places' children live only in the host's memory. Nothing ends such a process later. A restarted host has no record of it; `deploy/ubuntu/infinite.service` and the Linux user unit that `machine-cli.ts` writes set `KillMode=process`, so systemd leaves it running through the API's crash, restart and stop; and the macOS LaunchAgent that `machine-cli.ts` writes sets no `AbandonProcessGroup`, so launchd's default applies, which per launchd.plist(5) kills only the job's own process group, not the anchor's (taken from that documentation, not run on macOS). It runs until it exits on its own (its writes to the dead host's pipes fail with `SIGPIPE` or `EPIPE`), an operator ends it, or the machine restarts, and in a team run directory it holds a forced reconcile at 409 until then. The executor supervisors keep their own timer and stop when their input ends (`GROUP_SUPERVISOR`), so a host death alone does not leave their command running. `teamCommand` keeps its own copy of the rule (INF-400).

### 4. Launch-Rate Fuse, Project Signal Inbox, and Notifier (`fuse/*`, `signals/*`, `notifier.ts`)
- **Launch-rate fuse (`fuse/baseline.ts`, `fuse/rules.ts`, `fuse/service.ts`)**: The sealed baseline file is the single source of authority: mutations write the file first, then memory, then mirror best-effort to the evidence store. Without an authoritative baseline, `FuseService` holds an in-memory `unmeasurable` host trip and writes nothing until `tick` loads one. `mergeBaselines` uses the file's `seq` as a watermark so store-only rows at or before that `seq` stay deleted, and closed trips never reopen. `rollingCount` ignores owner closes stamped in the future (clock step-back protection), and `close` moves future-stamped launches back to `now` so the close clears them. `admit` keeps bounded (1,000) in-memory undo records so owner-halt refusals `refund` exact counts and unannounced trips before a restart. Failing baseline writes report `write-failed` once per UTC day and stay pinned in `applyFuseReason` until an admission or `tick` write succeeds; `plainLabel` strips Unicode `\p{C}\p{Zl}\p{Zp}\p{Bidi_Control}` before push bodies.
- **Project signal inbox (`signals/service.ts`, `signals/consume.ts`)**: `project_signals` uses `AUTOINCREMENT` so `seq` never repeats after pruning, blind-indexes `project`, and seals `project` and `kind` inside the payload so cross-project tampering fails authentication. Retention sweeps prune old rows past `MAX_SIGNAL_ROWS` (20,000) without removing dedupe keys (`project_signal_keys`, retained for `SIGNAL_RETENTION_DAYS`, capped at `MAX_SIGNAL_KEYS = 200,000` where excess writes refuse `"full"` instead of evicting keys); a `min(seq)`/`max(seq)` span check avoids counting rows until the span reaches the cap. `readSignals` starts unset cursors at head, skips DB reads when at head, resets cursors above head (replaced DB), caps pages at 200, and holds the cursor on read errors. `outsideCommit` triggers `external-commit` only for continuous scans with commits after the last non-`merge-parent` landing so multi-commit fast-forward/rebase deliveries never self-wake consumers.
- **Push notifier (`notifier.ts`)**: `start()` primes team/goal lifecycle baselines synchronously before the first interval. Learning sessions are never pushed. Open prompts share `promptOwner` with the decision queue and defer pushes for `REVIEW_START_GRACE_MS` (45s) up to `REVIEW_HOLD_LIMIT_MS` (8m) while the permission agent or team coordinator can still decide them. `fuse` and `mainCheck` notices mark delivered only when at least one device receives an ok ticket, retrying unreached notices after 60s (monotonic clock) rather than every tick. Long project IDs hash into bounded collapse IDs, and main-check pushes contain only host-generated metadata (never command output).

### 5. Transcript Capture, Usage Ledger, Provider Limits, and Context Telemetry (`transcript*.ts`, `opencode-usage.ts`, `hook-relay.ts`, `hooks.ts`, `final-drain.ts`, `usage*.ts`, `balances.ts`, `price-catalog.ts`, `provider-limits.ts`, `context-gauge.ts`, `context-touches.ts`, `check-metrics.ts`, `check-observations.ts`)
- **Agent-account hook relay and transcript watch (`hook-relay.ts`, `hooks.ts`, `final-drain.ts`, `transcript.ts`, `transcript-secondary.ts`, `transcript-watch.ts`)**: `hook-relay.ts` runs in the agent account, prints nothing, and always exits 0 so nothing becomes a provider hook decision. It streams primary and Claude subagent transcripts (`SECONDARY_NAME`, up to `MAX_SECONDARY_FILES = 64`, `MAX_CHUNKS = 64`, `MAX_SECONDARY_PASSES = 128`), verifying `<dev>:<ino>` on open for secondary files supplied by `streamWanted` (the primary transcript opens by `{ file: path }` without an inode identity comparison, so a primary end marker does not prove primary inode continuity across hook calls), cutting chunks on UTF-8 codepoint boundaries, and sending an end mark only as a text-less post once the worker's acknowledged cursor equals a fresh `fstat.size`. `final-drain.ts` invokes the `transcript-drain` wrapper via `sudo -n` bounded by `FINAL_DRAIN_MS` (10s). `TranscriptWatch` maintains sticky worst-case facts across replaced transcripts, treats post-stop `SessionEnd` as preserving the prior hook's turn boundary, requires `endOnly` (Codex notify) turn ends to be corroborated by a complete final drain plus `UsageTail.lastTurnEnded()`, and permanently marks replaced or shortened secondary files `broken`. `TranscriptTail` deduplicates messages by ID across retries and drops unterminated lines past `MAX_PARTIAL_LINE`.
