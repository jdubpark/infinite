# ADR-0022: CSS, Systemd Unit, and Remaining Test Harness Invariants

- **Status**: Accepted
- **Scope**: `apps/web/src/*.css`, `apps/web/src/swarm/*.css`, `apps/macos/Sources/InfiniteDesktop/Resources/terminal.css`, `deploy/ubuntu/**/*.service`, `deploy/ubuntu/**/*.timer`, `deploy/ubuntu/**/*.socket`, `scripts/check-comments.mjs`, and the final 26 commented files in `tests/`

## Context

Extending `scripts/check-comments.mjs` to cover CSS stylesheets (`.css`) and systemd unit files (`.service`, `.timer`, `.socket`) alongside clearing the remaining 26 commented `tests/` files (outside the concurrent `tests/halt.test.ts` change) surfaced non-obvious UI layout/accessibility contracts, Ubuntu service-hardening and firewall ordering rules, and test-harness invariants. This ADR preserves those decisions so all tracked CSS files, systemd unit files, and cleared test files remain at zero prose comments.

## Decisions

### 1. Comment checker coverage for CSS and systemd units (`scripts/check-comments.mjs`)
- **CSS (`.css`)**: Recognizes `/* ... */` block comments only. Never treats `//` (for example in `url(https://...)`) as a comment. Respects double- and single-quoted strings with backslash escapes (including escaped newlines), identifier backslash escapes, and unquoted `url(...)` tokens (skipping `/*` inside unquoted URLs while still detecting comments inside quoted `url("..." /* ... */)` calls and non-`url(` functions such as `my-url(/* ... */)`).
- **Systemd units (`.service`, `.timer`, `.socket`)**: Follows `systemd.syntax(7)`. Lines whose first non-whitespace character is `#` or `;` are full-line comments, including comment lines interspersed inside a `\`-continued directive. Inline `#` or `;` characters inside directive values (such as `ExecStart=...` or `Environment=...`) are never comments, and a trailing `\` on a comment line does not continue the comment onto the following line. Line-1 `#!` shebang exemptions apply only to script/source extensions and not to systemd units.

### 2. Web client CSS layout, accessibility, z-index, and theme invariants
- **Theme isolation and color-vision accessibility (`swarm.css`, `graph.css`, `views.css`, `style.css`)**:
  - `.swarm` scopes all `--sw-*` dark instrument variables locally so the rest of the web client keeps the paper/ink palette (`--paper`, `--ink`, `--muted`, `--rule`, `--green`).
  - Swarm state hues pass color-vision deficiency (CVD) separation and 3:1 contrast against `--sw-canvas`, and shape carries redundant state meaning for both agent marks and hold/terminal glyphs. Graph labels wear `--sw-ink*` tokens rather than state colors, and each graph link kind uses a distinct stroke/dash/opacity so touch kinds are never read as one.
  - Cost chart series slots (`--series-1` through `--series-6`) are assigned in fixed order per account and validated for CVD separation on `--paper`.
- **Floating chrome, stacking order, and click-through behavior (`style.css`, `swarm.css`, `graph.css`, `views.css`)**:
  - `.connection-notice` floats at `z-index: 5` (`position: absolute; pointer-events: none`) beneath `.topbar` over page title text rather than controls so it never intercepts clicks.
  - `.halt-banner` remains in normal document flow rather than floating because an owner halt persists until explicit release.
  - `.sw-top` and `.sw-bottom` float at `z-index: 2` with `pointer-events: none` while direct capsule children set `pointer-events: auto`, letting pointer events between capsules pass through to the edge-to-edge scrolling `.sw-canvas` (padded by `--sw-inset-top` and `--sw-inset-bottom` at rest).
  - Glass styling (`.sw-glass`) applies only to floating controls; graph legends, lanes, rows, and wall tiles stay flat with no shadows or blur. `@supports not (backdrop-filter)` and `prefers-reduced-transparency: reduce` fall back to `--sw-glass-opaque`.
  - `.sw-stage` sets `isolation: isolate` so `.sw-stage.sw-active::after` (`z-index: -1`) draws its highlight lens behind marks without dropping behind the canvas.
  - Graph node coordinates are computed deterministically in `graph-layout.ts` with no position animation; agents without host tool-input signals carry a dotted underline (`.sw-g-nosignal`).
- **Zero-reflow slots, truncation, and visual hierarchy (`style.css`, `decision-queue.css`, `swarm.css`)**:
  - `.workspace-navigation button` fixes a 72px tile with an absolutely positioned `.decision-nav-count` below the label so nav labels stay aligned when waiting counts appear.
  - `.team-detail-meta .team-workers` and `.team-freshness` take full width (`flex: 0 0 100%`) so count and waiting updates never reflow the header.
  - `.decision-queue-control` reserves a persistent `min-height: 46px` control line; `.decision-queue-notice` renders after card content with `position: sticky; bottom: 12px` so appearing notices never shift content above; `.decision-queue-card.is-stale` dims in place rather than clearing content; `.decision-queue-prompt .prompt-decision` sets `max-height: none; overflow: visible` because no composer sits below the prompt on the queue page.
  - `.sw-legend` and `.sw-inspector` stay always-present single-line bars. `.sw-inspector-fact` must remain a block box rather than a flex container so long facts truncate with `text-overflow: ellipsis` instead of mid-word clipping; `.sw-fixed` sets `flex: none; overflow: visible` so variable-length facts shrink first.
  - Selected decision options (`[aria-pressed="true"]`) outweigh recommended options via background fill and label, whereas recommendations use only border and tag styling.
- **Responsive rules (`style.css`, `swarm.css`)**:
  - At desktop width (`>= 701px`), `.app.swarm-shown .topbar` hides because the Swarm surface renders its own freshness slot.
  - At phone width (`<= 700px`), `.permission-overview-link` appears for single-pane navigation, `.halt-rail` repeats the halt notice only when the list stands alone (`.app:not(.has-detail)`), and `.halt-release` hides the terminal release command to keep room for the halt record.

### 3. Systemd unit hardening, firewall ordering, OOM/lifecycle, and socket-activation invariants
- **Control API unit (`deploy/ubuntu/infinite.service` and `scripts/render-instance.mjs`)**:
  - `KillMode=process` keeps session workers alive across API restarts; sessions are stopped explicitly.
  - `ProtectSystem=false` and `ProtectHome=false` allow agents on a personal host to update their own tools on the real read-write filesystem while credential files remain mode `0600`.
  - `NoNewPrivileges` is omitted because `sudo` must transition to `infinite-agent` for allowlisted native agents.
  - Secondary instances rendered by `scripts/render-instance.mjs` remove `MemoryHigh`/`MemoryMax`/`CPUQuota` ceilings and set `TasksMax=infinity`, `CPUWeight=50`, `IOWeight=50`, and `OOMScoreAdjust=500`.
- **nftables firewall units (`deploy/ubuntu/egress/infinite-egress-firewall.service`, `deploy/ubuntu/infinite-eval-firewall.service`, `deploy/ubuntu/infinite-grader-firewall.service`)**:
  - Ordered `After=nftables.service` and `Before=infinite.service` so rules install after any system ruleset flush and before the host starts agents, trials, or grading.
  - Coupled with `PartOf=nftables.service` and `ReloadPropagatedFrom=nftables.service` because restarting or reloading `nftables.service` flushes all tables, creating a brief unprotected window; active agents, trials, or validation must be stopped before modifying `nftables.service` or stopping a firewall unit.
  - `ExecStart` and `ExecReload` load an atomic `nft -f` file that deletes and recreates only its own table (`inet infinite_egress`, `inet infinite_eval`, `inet infinite_grader`), leaving other tables untouched and keeping the previous table active if loading fails.
  - Variant switches must use `systemctl reload`, never `restart`, because `restart` runs `ExecStop` (`nft delete table ...`) first and briefly removes enforcement. Stopping a firewall unit is the full rollback and restores direct network, private-range, and cloud-metadata access.
- **Egress proxy and optional socket activation (`deploy/ubuntu/egress/infinite-egress-proxy.service`, `infinite-egress-proxy.socket`)**:
  - `Environment=UV_THREADPOOL_SIZE=16` prevents slow DNS lookups from stalling concurrent libuv name resolutions.
  - `ExecReload=/bin/kill -HUP $MAINPID` reloads policy in place while keeping the last valid policy on load failure; `Restart=always` restores network access for proxied sessions automatically.
  - `StateDirectory=infinite-egress` (`0750`, `UMask=0027`) exposes `summary.json` (`0640`) to the host account via group `infinite-egress`.
  - `IPAddressDeny=link-local multicast` enforces kernel-level blocking of cloud metadata and multicast addresses beneath the proxy's own checks; the proxy holds no device keys or session tokens and never terminates TLS.
  - Optional `infinite-egress-proxy.socket` holds the listening loopback socket across proxy restarts so connections queue instead of failing with `ECONNREFUSED`. The proxy verifies the inherited socket is on loopback and exits otherwise; `ListenStream` must match `"listen"` in `/etc/infinite-egress/proxy.json` and the host's `proxyUrl`.
- **GitHub credential proxy (`deploy/ubuntu/infinite-github-proxy.service`) and relay (`deploy/ubuntu/infinite-relay.service`)**:
  - `infinite-github-proxy.service` uses `SupplementaryGroups=infinite-github-grant` solely to read the grant key shared with the host account, restarts unconditionally (`Restart=always`), logs one JSON line per request to the journal without tokens or grants, and runs `gh` inside `PrivateTmp=true` with `ProtectSystem=strict`.
  - `infinite-relay.service` sets `RuntimeDirectoryMode=0700` and `UMask=0077` so `proxy.sock` (`0600`) accepts connections only from root's `cloudflared` and not from agent accounts; the relay holds no device keys.

### 4. Remaining test harness, simulator, and contract invariants (26 `tests/` files)
- **Process cleanup and leak detection (`fixture-stop.test.ts`, `intake-e2e.test.ts`)**:
  - Zombie processes waiting to be reaped retain a process-table row without a command line; `running()` checks both PID and `WORKER_ENTRY` in `command`.
  - Startup-race tests leave `fetchApi("/sessions")` unawaited so `host.stop()` meets the worker before any PID is recorded; `endSessionWorkers` is tested directly without `host.stop()`'s fixed wait (which would mask an early return); `finally` kills any leaked worker before a fallback stop.
  - `intake-e2e.test.ts` detects surviving agents by matching the per-test `receipts` directory path present on every agent command line.
- **Seeded simulators (`fixtures/delivery-review-sim.ts`, `fixtures/goal-plan-sim.ts`, `fixtures/goal-agent.mjs`, `main-check-sim.test.ts`, `team-register.test.ts`)**:
  - `delivery-review-sim.ts` tracks observed author families and reviewed heads in a reference oracle against real Git integration and sealed receipts; its `skip-family-gate` mutant alters only the gate input to model checking a nominal lineup instead of sealed writers.
  - `goal-plan-sim.ts` restarts `TeamService` after pin preparation, correction save, or outcome acceptance (reopening sealed records via `TeamService`) and checks invariants I1–I3 (exact objective-version pin preservation, single non-renewable correction per revision across restarts, and accepted task links never composing an assessment). Parity-alternating `followUp` ensures the 12-seed default corpus covers both acceptance and blocking. `fixtures/goal-agent.mjs` auto-attaches criterion `c0` when prompted with goal-plan criterion instructions.
  - `main-check-sim.test.ts` replays via `MAIN_CHECK_SIM_SEED`/`SEEDS`/`BASE`, sets corpus floors at roughly half of baseline counts (thinnest cases 3–8 runs), omits a floor for single-hit `command:drain-stopped` (covered deterministically by `tests/team-command-leader.test.ts`), and injects mutants via in-process instance patching without editing source files.
  - `team-register.test.ts` reads `w.holders` dynamically so simulated restarts replace holders with JSON round-trip copies even mid-read, models `continue`/recovery holder cloning (`Object.assign(holder, structuredClone(holder))`) both queued and mid-read, and asserts `applied > SEEDS / 4` so seeded invariants cannot pass vacuously.
- **Provider launch, trust, and permission-channel checks (`host-launch.test.ts`, `permission-session-requests.test.ts`, `team-permissions.test.ts`)**:
  - Claude Code honors only the last `--settings` flag; when no hook layer is attached, `buildLaunch` omits its standalone Code Mode `--settings` argument if the profile already supplies `--settings`, whereas with signal hooks enabled the host appends its hook `--settings` (pinning `disableAllHooks: false` so project settings cannot turn host hooks off) after the profile's arguments; served headless Claude replaces signal-relay `PermissionRequest` with `permission-hook.js request` alone so owners are not prematurely pushed while the permission agent decides.
  - Out-of-range native argument counts inject nothing (protecting `sudo` options). `missionCoordinatorLaunch` accepts only `MissionCoordinatorProvider` (`"claude"`), strips variadic flags (`--tools`, `--mcp-config`) so stray values never become positional prompts, and fails closed at runtime; non-Claude mission coordinators are formally excluded by `missionCoordinatorProviderSchema`, `missionLineupSchema`, `validateIntakeConfig`, and `MissionService.enabled()` because Codex deep-merges inherited MCP server tables and cannot isolate them safely across `sudo`/auth boundaries.
  - Codex `-c` TOML encoding escapes raw DEL (`\x7f`) as `\u007f` because TOML rejects raw DEL in basic strings while JSON leaves it raw; dev hook relay resolves an absolute `file:///` `tsx` loader independent of agent cwd; trusted Codex launches pin `project_root_markers=[".git"]`, treat worktree `.git` files as roots, skip `.git` directories lacking `HEAD`, and reject `.codex` entries in the launch directory and its ancestors through the detected project root (or only the launch directory when no root marker exists; siblings and descendants are not scanned).
  - Claude config lock tests mirror `proper-lockfile` 10-second staleness reclamation and prompt failure on non-empty lock directories; symlink-invoked `workspace-trust` tests mirror Ubuntu's `/opt/infinite` release symlink.
  - `permission-session-requests.test.ts` pins headless-channel exclusion, authoritative `meta` session-record lookup over stale listing rows, unique non-persistent one-shot reject eligibility, session-root jailing (never walking upward to parent `.git`), and bounded event-log reads (missed earlier prompts add a limitation note without withholding; unreadable new tail withholds delivery).
  - `team-permissions.test.ts` waits for `check-ready.json` before `pause`/`cancel` so API restart deterministically interrupts the held check rather than racing past the preceding quick check.
- **Mocked-clock polling, rate-limit, fuse, eval-pump, and backward-compatibility pins (`linear-budget.test.ts`, `standing-goals.test.ts`, `fuse-baseline.test.ts`, `fuse-rules.test.ts`, `routines.test.ts`, `objective-goals.test.ts`, `eval-trial-pump.test.ts`, `eval-trial-run.test.ts`, `judge-pump-lifecycle.test.ts`, `intake-slack.test.ts`, `intake-store.test.ts`, `team-goal-criteria.test.ts`)**:
  - Suites mocking `Date` (`linear-budget.test.ts`, `standing-goals.test.ts`) poll with attempt counts or `performance.now()` because `Date.now()` is frozen.
  - `linear-budget.test.ts` pins exact-size GraphQL `first` arguments (Linear prices by page size), `Retry-After` precedence over reset headers, the 5-minute probe cap on long reset windows without `Retry-After`, exponential backoff, and single-probe gating.
  - `fuse-baseline.test.ts` and `fuse-rules.test.ts` pin file-first merge authority (store-only entries at `<= file.seq` remain dropped), unbounded project ID lengths, backward clock-step resilience (future `closedAt` is ignored until clock passes it), owner-close trip precedence after merge, and `admit`-only clearing of `write-failed`.
  - `routines.test.ts` and `standing-goals.test.ts` preserve pre-feature approval/request fingerprints (`f0153ac5...` without `wakeOn`; legacy `parseCreateGoal` key order with `maxRuns: 3`), test 51-signal batches spanning the 50-signal pass cap plus unreadable-inbox deferral, and test UTF-8 byte caps on standing objectives (9,000 Hangul syllables = 27,000 bytes > 24,000-byte limit while passing the 12,000-char schema check).
  - `objective-goals.test.ts` supplies dummy `process.execPath` provider profiles for lineup validation, hand-reseals records to construct shapes rejected by the production writer, exercises 6,144-byte digest and 32 KiB record caps (via 8×1,000-byte criteria and 20×300 control characters whose JSON escapes exceed 32 KiB), and wraps `schedulerFixture`'s `manager.state` as active because `schedulerFixture` defaults sessions to 6 minutes quiet against `stallMinutes: 5` for stall tests.
  - `eval-trial-pump.test.ts`, `eval-trial-run.test.ts`, and `judge-pump-lifecycle.test.ts` bound pump step loops against hangs and model failed post-trial/post-judgement `clean` calls (omitting `scrub` on failure and forcing a full `stop, clean, scrub` start-up reset before the next workspace build).
  - `intake-slack.test.ts` and `intake-store.test.ts` use an uncovered configured project path (`/data/instances/work/api`) for redaction tests, seed thread roots in the fake Slack server, pre-assign question numbers in shared-thread tests to avoid composition-order races, verify persisted `inbound.call` crash replay and `event_id`/`ts` deduplication, and keep retryable `pending` replies (even with `error`) ahead of terminal `failed` replies during 400-message trimming.
  - `team-goal-criteria.test.ts` reuses the fixture's initial PM with a real scheduler session so `replaceStalledMember` exercises the real stop/requeue path.

## Consequences

- `scripts/check-comments.mjs` now enforces zero prose comments on all `.css`, `.service`, `.timer`, and `.socket` files in addition to existing code and script extensions.
- All 6 tracked CSS files, all 12 tracked systemd unit files, and all cleared `tests/` files (every `tests/` file except concurrent `tests/halt.test.ts`) carry zero prose comments while preserving all non-obvious layout, security, firewall, and test-harness rationale here.
