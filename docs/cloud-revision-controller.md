# Cloud revision controller

The controller accepts signed GitHub `push` and `pull_request` deliveries for one enrolled repository and its allowlisted target branches. It records each accepted delivery before acknowledging it, publishes a pending commit status for the event's SHA, and keeps a durable SHA-keyed job until the final status is published. The worker retries interrupted or unpublished jobs. A repeated delivery or a push and PR event for the same SHA and enrollment share one job.

Install `scripts/cloud-revision.py` as trusted controller code. Create a private enrollment JSON from `scripts/cloud-revision/enrollment.example.json`, with mode `0600`, and set `stateDirectory` to a controller-owned directory with mode `0700`. The example uses placeholders. `snapshotRoot` must be inside the enrolled workspace roots used by `infinite-check`; the installed launcher, runner alias, origin and workspace must already be enrolled there. Pin `profileSha256` to the approved `scripts/cloud-check/linux-runner.json` digest. Set `mode` to `npm` with `command` exactly `npm run check` for standard locked `npm ci` checks, `compose` with an empty command for an enrolled `.infinite/check.json` recipe, or `command` with the operator-owned argv passed to `infinite-check --project-command`. The target repository cannot replace the launcher or its enrolled command. The controller pins the installed launcher, its guest helpers and its toolchain inputs on first start and refuses changed enrollment in an existing state directory. A launcher, command, profile, runner or target change needs a new status context and state directory so earlier statuses cannot be reused.

Store `webhookSecretFile` and `githubTokenFile` as separate mode `0600` files. The bearer token needs permission to create repository commit statuses. The publisher uses GitHub's REST commit-status endpoint at `https://api.github.com` by default; pass `--api API_BASE` to both service commands for a different GitHub API base. For immediate delivery of individual updates, configure the GitHub webhook to send `push` and `pull_request` events, use the same secret, and forward `POST /github-webhook` through a TLS reverse proxy to `127.0.0.1:8418`. The controller verifies the HMAC, repository, base branch and head SHA. It rejects fork heads and deliveries for other repositories or branches. Never expose the loopback listener directly to the network.

Install the observer and worker timer examples under the host's systemd configuration. The observer queries the enrolled branch tips and open pull requests every five minutes over outbound HTTPS. It admits a pull request only when both sides belong to the enrolled repository and its base branch is in scope. It shares the webhook queue, so a duplicate observation keeps the original result. After a controller outage this recovers current heads. Capturing a head that was pushed and replaced between polls requires webhook delivery. A private repository also needs read access to its contents and pull requests.

The worker timer checks the queue every 30 seconds. A publisher outage leaves a completed check and its receipt available for publication when credentials recover. Configure the receiver service when using webhooks. Run a real revision before making the context required. A maintainer can qualify a fork contribution by bringing its reviewed head into an enrolled branch in the owning repository.

A fully captured, digest-matched output containing only repeated enrolled-runner dispatch/BUSY pairs and the capacity-expired diagnostic, with no receipt created, is recorded as an admission wait and returned to the pending queue for a later worker tick. These waits do not consume the verification retry budget; total attempts remain monotonic, and the parser rejects truncated or oversized logs and any extra output. A previously published missing-receipt error is recovered only when its complete saved output proves this same pre-transfer outcome, with the original terminal record and log retained.

Each run fetches the event SHA from the configured origin into a temporary clean checkout under `snapshotRoot`. Git system/global configuration and checkout hooks are disabled during capture, and the controller never executes target checkout code. Only the configured launcher command is dispatched to the enrolled guest. The private job record includes the complete output digest and byte count. Its sibling `.log` contains the last MiB for diagnosis. The check's own cloud receipt remains the source for runner and toolchain evidence; the controller records its exit, output digest, source SHA, command/profile enrollment digest and status publication outcome in its private state. A later SHA receives its own pending status and cannot inherit an earlier pass.
