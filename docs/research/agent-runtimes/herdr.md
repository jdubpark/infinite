# How Herdr coordinates agents in terminal panes

## Scope and source

This review follows Herdr source at commit [`e8d7d9705a7a2c89cef4dd42079379f05685af87`](https://github.com/herdrdev/herdr/tree/e8d7d9705a7a2c89cef4dd42079379f05685af87). Herdr owns terminal panes and their processes. Each provider CLI handles inference and coding. The reviewed API controls those runtimes and observes their lifecycle.

## Topology and identity

One Herdr server owns a local session, a local IPC endpoint, and a tree of workspaces, tabs, panes, terminal runtimes, and processes. Unix uses filesystem sockets with mode 0600. Windows uses a namespaced local socket with a security descriptor. Human clients use the terminal UI, and agents use the CLI/API against that server. Saved SSH machines are separate remote sessions reached through forwarding. [Platform-specific local IPC](https://github.com/herdrdev/herdr/blob/e8d7d9705a7a2c89cef4dd42079379f05685af87/src/ipc.rs#L99-L125) [Unix socket permission mode](https://github.com/herdrdev/herdr/blob/e8d7d9705a7a2c89cef4dd42079379f05685af87/src/api/server.rs#L27-L30)

Herdr identifies an agent through the live process occupying a pane. Pane and terminal IDs are Herdr handles. The provider session reference is separate metadata with a provider, agent kind, and native ID or path. The actual OS process is a third identity. Agent names are live aliases that follow pane occupants and clear when an agent exits or is replaced. Panes can also host ordinary shells and commands. [Agent API and provider session reference](https://github.com/herdrdev/herdr/blob/e8d7d9705a7a2c89cef4dd42079379f05685af87/src/api/schema/agents.rs#L209-L260) [Agent identity and target rules](https://github.com/herdrdev/herdr/blob/e8d7d9705a7a2c89cef4dd42079379f05685af87/skills/herdr/SKILL.md#L51-L59)

## Normal start, dispatch, and reply flow

An agent can split a pane, start a supported CLI in an available shell pane, and prompt a sibling by name or pane ID. `agent start` refuses occupied panes, validates the name/kind/arguments and shell input, sends the launch command into the existing shell, then waits for recognition/readiness in that same pane. The documented default is a sibling pane in the same working directory. A parallel writer would share that directory unless a caller creates a separate checkout. [Default coordination topology](https://github.com/herdrdev/herdr/blob/e8d7d9705a7a2c89cef4dd42079379f05685af87/skills/herdr/SKILL.md#L107-L111) · [CLI readiness wait](https://github.com/herdrdev/herdr/blob/e8d7d9705a7a2c89cef4dd42079379f05685af87/src/cli/agent.rs#L324-L343) · [Start implementation](https://github.com/herdrdev/herdr/blob/e8d7d9705a7a2c89cef4dd42079379f05685af87/src/app/agents.rs#L145-L235)

`agent prompt` validates the target, then queues encoded text and Enter to its PTY. It refuses unknown, non-foreground, unready, or blocked targets. The API reports input-submission completion. With `--wait`, it waits for lifecycle activity and a settled state. When the agent was already working, the active turn may satisfy that wait. These state transitions carry no durable prompt/task ID. [Prompt validation and PTY submission](https://github.com/herdrdev/herdr/blob/e8d7d9705a7a2c89cef4dd42079379f05685af87/src/app/api/agents.rs#L139-L268) [Prompt activity and settled wait](https://github.com/herdrdev/herdr/blob/e8d7d9705a7a2c89cef4dd42079379f05685af87/src/api/wait.rs#L177-L320)

In a normal flow, coordinator A splits a sibling pane, starts Codex as B, waits until B is ready, sends a task prompt, then waits for B to settle. B replies in its terminal transcript. A reads that output or asks B to write a report. Herdr's `agent.read` returns terminal output. The skill warns that a settled status does not prove background subagents or work have finished. [Coordination guidance and wait semantics](https://github.com/herdrdev/herdr/blob/e8d7d9705a7a2c89cef4dd42079379f05685af87/skills/herdr/SKILL.md#L107-L171)

## State, persistence, and failure semantics

Herdr recognizes working, blocked, idle, done, and unknown states from provider hooks, metadata, and terminal-screen detection. It checks the provider/source pair before granting a hook full lifecycle authority. Unknown reports insufficient evidence. Blocked indicates a recognized UI requiring input. The CLI/API methods cover list/get/read/start/prompt/wait and pane/workspace control. [Detection inputs and hook authority](https://github.com/herdrdev/herdr/blob/e8d7d9705a7a2c89cef4dd42079379f05685af87/src/detect/mod.rs#L304-L347) · [Agent methods](https://github.com/herdrdev/herdr/blob/e8d7d9705a7a2c89cef4dd42079379f05685af87/src/api/schema.rs#L81-L92)

When session persistence is enabled, a debounced snapshot stores workspace/tab/pane layout, working directories, names, launch metadata, supported provider session references, and optionally terminal history. [Save scheduling and capture](https://github.com/herdrdev/herdr/blob/e8d7d9705a7a2c89cef4dd42079379f05685af87/src/app/session.rs#L14-L90) [Snapshot and pane metadata](https://github.com/herdrdev/herdr/blob/e8d7d9705a7a2c89cef4dd42079379f05685af87/src/persist/snapshot.rs#L11-L134)

Cold restart creates fresh shells in saved working directories. When resume is enabled, Herdr builds native CLI resume commands for supported provider/session pairs, deduplicates provider references, and defers launch until the pane is ready to render. A missing directory or shell failure leaves a pane with a restore error. A supported provider session can be reopened from its native reference. [Fresh-shell restore contract](https://github.com/herdrdev/herdr/blob/e8d7d9705a7a2c89cef4dd42079379f05685af87/src/persist/restore.rs#L65-L92) [Resume allowlist and duplicate suppression](https://github.com/herdrdev/herdr/blob/e8d7d9705a7a2c89cef4dd42079379f05685af87/src/persist/restore.rs#L813-L890)

Herdr supports a controlled `server.live_handoff` path for replacing its Unix headless server during a live update. Runtime file descriptors and pane state move to the replacement, keeping the PTY and process alive. Requests, waits, subscriptions, client sockets, and pane-to-pane messages are transient. Clients reconnect and inspect the target before retrying an operation that may already have taken effect. [Transferred runtime and transient state boundary](https://github.com/herdrdev/herdr/blob/e8d7d9705a7a2c89cef4dd42079379f05685af87/src/handoff_runtime.rs#L4-L32) [Descriptor transfer and ownership commit](https://github.com/herdrdev/herdr/blob/e8d7d9705a7a2c89cef4dd42079379f05685af87/src/server/headless/lifecycle.rs#L130-L220)

Event subscriptions provide short-lived coordination signals. The in-memory event hub retains up to 512 sequenced events. Supported subscriptions that fall behind receive `events_lost` and must resubscribe and resync with `session.snapshot`. Other subscriptions sample current state. Treat this bounded runtime history as an operational signal. [Bounded event retention](https://github.com/herdrdev/herdr/blob/e8d7d9705a7a2c89cef4dd42079379f05685af87/src/api/event_hub.rs#L18-L67) [Lost-history handling and resync](https://github.com/herdrdev/herdr/blob/e8d7d9705a7a2c89cef4dd42079379f05685af87/src/api/subscriptions.rs#L317-L340)

When B is blocked at an approval or question UI, validation returns `agent_blocked` before changing the pane or sending input. A timeout or stalled response is ambiguous because the prompt may already have reached the terminal. Waits observe lifecycle state, so a prior active turn can satisfy a settled-state wait. Inspect state and output before retrying.

## Debugging a misleading observation

Herdr separates pure application state from the live registry of PTYs, parsers and runtime handles. Its adversarial identity test mutates a pane layout and checks structural invariants. Its detection rules can be reloaded and explained, including which screen evidence matched. A provider hook with lifecycle authority follows a different explanation path. For Infinite, a diagnostic that shows the origin and age of an apparent block would let the coordinator request fresh evidence before treating a display change as task progress. [State model](https://github.com/herdrdev/herdr/blob/e8d7d9705a7a2c89cef4dd42079379f05685af87/src/app/state.rs#L890-L919) · [Runtime registry](https://github.com/herdrdev/herdr/blob/e8d7d9705a7a2c89cef4dd42079379f05685af87/src/terminal/runtime_registry.rs#L5-L21) · [Identity invariant test](https://github.com/herdrdev/herdr/blob/e8d7d9705a7a2c89cef4dd42079379f05685af87/src/app/state.rs#L1471-L1485) · [Rule reload](https://github.com/herdrdev/herdr/blob/e8d7d9705a7a2c89cef4dd42079379f05685af87/src/detect/manifest.rs#L275-L318) · [Explain response](https://github.com/herdrdev/herdr/blob/e8d7d9705a7a2c89cef4dd42079379f05685af87/src/app/api/agents.rs#L332-L378).

When restore was requested but the snapshot could not be loaded, the writer protects the existing file. It must preserve its bytes before replacing them and can retry after archival fails. This pattern fits sealed evidence recovery if an unreadable record is surfaced for reconciliation. At the client boundary, a quiet endpoint can be probed before it is declared disconnected. A connection-health result still leaves the remote process and assignment to be checked. [Guarded snapshot write](https://github.com/herdrdev/herdr/blob/e8d7d9705a7a2c89cef4dd42079379f05685af87/src/persist/writer.rs#L15-L49) · [Failed archival test](https://github.com/herdrdev/herdr/blob/e8d7d9705a7a2c89cef4dd42079379f05685af87/src/persist/writer.rs#L471-L505) · [Endpoint health](https://github.com/herdrdev/herdr/blob/e8d7d9705a7a2c89cef4dd42079379f05685af87/src/client/endpoint/health.rs#L33-L71).

## Boundaries and transfer to unattended work

Herdr runs existing providers in user shells and can use inherited environment and SSH-agent credentials. In the reviewed agent API, provider permission decisions remain inside each provider and no per-task tool scope is exposed. Herdr's blocked-state gate prevents a prompt from being sent into a recognized approval/question screen. [Inherited SSH-agent boundary](https://github.com/herdrdev/herdr/blob/e8d7d9705a7a2c89cef4dd42079379f05685af87/src/api/server.rs#L95-L105)

Herdr can supply runtime topology, pane/terminal handles, visible lifecycle and blocker signals, sibling-agent PTY coordination, and provider-native session resume. Infinite already supplies the durable assignment, report, and receipt layer. Map Herdr runtime identities, event signals, and process handoffs into that workflow, recording bounded events and uncorrelated waits as runtime observations.
