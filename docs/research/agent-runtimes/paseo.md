# How Paseo coordinates daemon-owned agents and provider conversations

This study follows `getpaseo/paseo` commit [`cf1a5a9e73a6dd3020fb62a6d10281a2193ff2f2`](https://github.com/getpaseo/paseo/tree/cf1a5a9e73a6dd3020fb62a6d10281a2193ff2f2), dated 2026-11-24. Statements about Hub’s external event service come from first-party documentation. The service implementation is outside this source tree.

## Runtime and state ownership

Paseo is a host-centered runtime. A Node daemon owns provider adapters, workspaces, agent lifecycle, tools, and client subscriptions. Desktop, mobile, web, CLI, and SDK clients connect by WebSocket. An optional outbound encrypted relay carries remote client traffic to that daemon. Agent placement and execution remain daemon-owned. MCP adapts the daemon’s transport-neutral tool catalog. [Architecture and relay](https://github.com/getpaseo/paseo/blob/cf1a5a9e73a6dd3020fb62a6d10281a2193ff2f2/docs/architecture.md#L1-L56), [module ownership](https://github.com/getpaseo/paseo/blob/cf1a5a9e73a6dd3020fb62a6d10281a2193ff2f2/docs/architecture.md#L87-L103).

`AgentManager` owns live lifecycle and in-memory timeline projections. `AgentStorage` persists JSON records with the Paseo ID, provider, cwd/workspace, labels, metadata, config, owner, status, and provider persistence handle. The provider adapter owns conversation restoration. The production bootstrap supplies agent metadata storage and leaves the manager's optional durable timeline store unset. The default timeline projection lives in memory. Provider history can seed it again on resume. [Daemon bootstrap](https://github.com/getpaseo/paseo/blob/cf1a5a9e73a6dd3020fb62a6d10281a2193ff2f2/packages/server/src/server/bootstrap.ts#L1047-L1062) · [Optional durable seed](https://github.com/getpaseo/paseo/blob/cf1a5a9e73a6dd3020fb62a6d10281a2193ff2f2/packages/server/src/server/agent/agent-manager.ts#L4721-L4735). [Stored record](https://github.com/getpaseo/paseo/blob/cf1a5a9e73a6dd3020fb62a6d10281a2193ff2f2/packages/server/src/server/agent/agent-storage.ts#L44-L94), [manager](https://github.com/getpaseo/paseo/blob/cf1a5a9e73a6dd3020fb62a6d10281a2193ff2f2/packages/server/src/server/agent/agent-manager.ts#L900-L965), [persistence boundary and resume](https://github.com/getpaseo/paseo/blob/cf1a5a9e73a6dd3020fb62a6d10281a2193ff2f2/docs/architecture.md#L396-L405).

Agent-scoped `create_agent` uses the caller’s workspace by default and records parentage explicitly. Parentage drives subagent display and archive and detach behavior. Authorization still comes from daemon grants, and the flow has no task-acceptance contract. Some providers expose native child sessions. Paseo tracks these under a parent while the provider retains runtime ownership. [Creation and parent labels](https://github.com/getpaseo/paseo/blob/cf1a5a9e73a6dd3020fb62a6d10281a2193ff2f2/packages/server/src/server/agent/tools/paseo-tools.ts#L1619-L1687), [relationship lifecycle](https://github.com/getpaseo/paseo/blob/cf1a5a9e73a6dd3020fb62a6d10281a2193ff2f2/docs/agent-lifecycle.md#L120-L151), [provider children](https://github.com/getpaseo/paseo/blob/cf1a5a9e73a6dd3020fb62a6d10281a2193ff2f2/docs/agent-lifecycle.md#L205-L207).

## Delivery and creation identity

**Recipient inbox.** `AgentMessageDelivery` keeps an in-memory ordered queue per recipient. An agent message can wait for the current turn, steer it, or interrupt it. Queue mode waits for the current turn. An idle recipient gets a quiet window capped at ten seconds. Batching, stop holds, and failed-start handback coordinate concurrent prompts. A queued receipt acknowledges admission. The inbox stays in memory, and reviewed code shows no queue-size bound. [Queue owner](https://github.com/getpaseo/paseo/blob/cf1a5a9e73a6dd3020fb62a6d10281a2193ff2f2/packages/server/src/server/agent/agent-messages/delivery.ts#L195-L249), [admission](https://github.com/getpaseo/paseo/blob/cf1a5a9e73a6dd3020fb62a6d10281a2193ff2f2/packages/server/src/server/agent/agent-messages/delivery.ts#L572-L603), [queue timing](https://github.com/getpaseo/paseo/blob/cf1a5a9e73a6dd3020fb62a6d10281a2193ff2f2/docs/agent-lifecycle.md#L153-L160).

**Message receipt.** When `messageId` is supplied, `MessageReceipts` journals the request hash and state atomically. An identical completed request can be retried safely. Reusing the ID with different content conflicts. An existing pending receipt returns `agent_request_outcome_unknown`, because the provider may have accepted the prompt before the completion write. The receipt is keyed to agent plus message ID and tracks request identity. A crash after the pending write can leave an unknown outcome even if a queued prompt vanished with process memory. A direct send rejected before handoff can retry the same ID. An agent-originated send may reply “queued” while dispatch is still pending. Choosing a new ID after an ambiguous dispatch can duplicate work. [Receipt implementation](https://github.com/getpaseo/paseo/blob/cf1a5a9e73a6dd3020fb62a6d10281a2193ff2f2/packages/server/src/server/message-receipts/index.ts#L23-L61), [session send path](https://github.com/getpaseo/paseo/blob/cf1a5a9e73a6dd3020fb62a6d10281a2193ff2f2/packages/server/src/server/session.ts#L9239-L9256), [receipt contract](https://github.com/getpaseo/paseo/blob/cf1a5a9e73a6dd3020fb62a6d10281a2193ff2f2/docs/hub.md#L50-L71).

**Creation identity.** The ordinary create RPC has a separate, daemon-wide idempotency key. A keyed create omits the initial prompt and journals the allocated ID before creation. After a lost reply the caller can recover the same agent, then send the first prompt with its own stable message ID. Workspace creation has a separate key namespace. [Ordinary RPC retry contract](https://github.com/getpaseo/paseo/blob/cf1a5a9e73a6dd3020fb62a6d10281a2193ff2f2/docs/hub.md#L49-L72).

**Finish subscription.** A daemon watch handles finish, error, and permission callbacks. A `FinishSubscription` persists caller, child, optional remote server, and parent-ownership requirement in an atomically rewritten JSON file. On daemon start, subscriptions are reattached. A replacement is stored before dispatch and supersedes its predecessor only after the prompt is accepted. Rejected dispatch preserves the prior subscription. The observer waits for dispatch acknowledgement before retiring a terminal notification. A permission checkpoint leaves the subscription active so it can notify again when the child settles. Storage or delivery errors retry. Remote observation retries connection/unreachable errors, then reports host-unreachable/removed as a loss of visibility. The child's outcome remains unknown. [Subscription store](https://github.com/getpaseo/paseo/blob/cf1a5a9e73a6dd3020fb62a6d10281a2193ff2f2/packages/server/src/server/agent/finish-subscriptions/internal/json-store.ts#L7-L57), [acknowledgment, retry, and supersession](https://github.com/getpaseo/paseo/blob/cf1a5a9e73a6dd3020fb62a6d10281a2193ff2f2/packages/server/src/server/agent/finish-subscriptions/index.ts#L72-L114), [delivery and remote failure](https://github.com/getpaseo/paseo/blob/cf1a5a9e73a6dd3020fb62a6d10281a2193ff2f2/packages/server/src/server/agent/finish-subscriptions/index.ts#L170-L255), [restart reattachment](https://github.com/getpaseo/paseo/blob/cf1a5a9e73a6dd3020fb62a6d10281a2193ff2f2/packages/server/src/server/bootstrap.ts#L1983-L1988).

In a normal delegation, a parent creates a child asynchronously, may get a persisted finish subscription, then sends later prompts through the recipient inbox. A message receipt journals identity only when a caller supplies `messageId`. If the daemon crashes, provider transcript and agent record can survive while the inbox is lost. Startup agent recovery is off by default and best effort. Eligible interrupted agents resume under existing IDs and receive a continuation prompt. A crash can lose or repeat that continuation. [Restart policy](https://github.com/getpaseo/paseo/blob/cf1a5a9e73a6dd3020fb62a6d10281a2193ff2f2/docs/agent-lifecycle.md#L15-L34).

Timeline events stream live. Reconnect uses an epoch and sequence cursor and pages to the current head. When the epoch changes or the cursor predates the retained window, the daemon signals a reset and returns the current tail. Provider history can rebuild the agent projection after resume. [Cursor reset](https://github.com/getpaseo/paseo/blob/cf1a5a9e73a6dd3020fb62a6d10281a2193ff2f2/packages/server/src/server/agent/agent-timeline-store.ts#L101-L132) · [Timeline catch-up](https://github.com/getpaseo/paseo/blob/cf1a5a9e73a6dd3020fb62a6d10281a2193ff2f2/docs/timeline-sync.md#L46-L64), [timeline ownership](https://github.com/getpaseo/paseo/blob/cf1a5a9e73a6dd3020fb62a6d10281a2193ff2f2/docs/architecture.md#L396-L405).

## Remote tools and waiting

At this pin, seven MCP host operations accept optional `serverId`. They create an agent or workspace, list workspaces or agents, send a prompt, get status, and get activity. The resolver routes these over the connected-host path and rejects remote use for a caller locked to a local cwd. Remote child creation and prompt sends register finish subscriptions on the caller’s daemon. Creation callbacks also verify that the child still belongs to the caller. Thus parent callbacks can span hosts, subject to the host link and its admission. [Routed tool set and handler](https://github.com/getpaseo/paseo/blob/cf1a5a9e73a6dd3020fb62a6d10281a2193ff2f2/packages/server/src/server/agent/tools/paseo-tools.ts#L682-L720), [server selection](https://github.com/getpaseo/paseo/blob/cf1a5a9e73a6dd3020fb62a6d10281a2193ff2f2/packages/server/src/server/agent/tools/paseo-tools.ts#L724-L815), [remote host resolver](https://github.com/getpaseo/paseo/blob/cf1a5a9e73a6dd3020fb62a6d10281a2193ff2f2/packages/server/src/server/agent/host-operations/index.ts#L84-L106).

MCP `create_agent` and `send_agent_prompt` return before completion. The documented MCP tools provide status/activity polling and notifications. An agent can return to its own work after subscribing. `waitForFinish()` is a TypeScript SDK method with `idle`, `permission`, `error`, and `timeout` outcomes. Timeout leaves the agent running. [MCP tool list](https://github.com/getpaseo/paseo/blob/cf1a5a9e73a6dd3020fb62a6d10281a2193ff2f2/public-docs/mcp.md#L86-L103), [SDK wait](https://github.com/getpaseo/paseo/blob/cf1a5a9e73a6dd3020fb62a6d10281a2193ff2f2/public-docs/sdk/agents.md#L25-L38).

Daemon principals authorize workspace reads/writes, management, and automation with semantic grants. `hub.execute` is daemon-wide. Parent-child labels affect lifecycle and reporting while session grants authorize operations. [Permission model](https://github.com/getpaseo/paseo/blob/cf1a5a9e73a6dd3020fb62a6d10281a2193ff2f2/docs/permissions.md#L1-L55), [Hub scope](https://github.com/getpaseo/paseo/blob/cf1a5a9e73a6dd3020fb62a6d10281a2193ff2f2/docs/hub.md#L28-L35).

## Automation and limits

The OSS daemon’s `ScheduleService` persists schedule/run state under the daemon home. It claims a due slot and advances `nextRunAt` in one serialized update. On restart, it marks a running schedule run failed, advances past missed cadence slots, and archives an interrupted workspace when configured. Local schedules create fresh agents. Heartbeats prompt an existing agent. [Schedule storage](https://github.com/getpaseo/paseo/blob/cf1a5a9e73a6dd3020fb62a6d10281a2193ff2f2/packages/server/src/server/schedule/service.ts#L295-L325), [slot claim](https://github.com/getpaseo/paseo/blob/cf1a5a9e73a6dd3020fb62a6d10281a2193ff2f2/packages/server/src/server/schedule/service.ts#L838-L887), [interrupted-run recovery](https://github.com/getpaseo/paseo/blob/cf1a5a9e73a6dd3020fb62a6d10281a2193ff2f2/packages/server/src/server/schedule/service.ts#L664-L750), [schedule semantics](https://github.com/getpaseo/paseo/blob/cf1a5a9e73a6dd3020fb62a6d10281a2193ff2f2/public-docs/schedules.md#L9-L22).

The Hub documentation describes an orchestration service that verifies external events, matches triggers, tracks execution records, and uses daemon RPC to start or continue agents. The daemon implements Hub enrollment and execution permissions. Hub event ingestion and trigger service are outside this repository. The Hub schedule documentation promises one catch-up run for the earliest missed occurrence and skips new occurrences while that trigger is still active. The local daemon and Hub therefore have distinct recovery policies. `hub.execute` grants a Hub session daemon-wide agent authority. [Hub schedule policy](https://github.com/getpaseo/paseo/blob/cf1a5a9e73a6dd3020fb62a6d10281a2193ff2f2/public-docs/hub/triggers/schedules.md#L78-L85) · [Hub event path](https://github.com/getpaseo/paseo/blob/cf1a5a9e73a6dd3020fb62a6d10281a2193ff2f2/public-docs/hub/concepts.md#L9-L40), [daemon Hub scope](https://github.com/getpaseo/paseo/blob/cf1a5a9e73a6dd3020fb62a6d10281a2193ff2f2/docs/hub.md#L28-L48).

`packages/server/src/tasks` contains a file-backed task DAG. A scan found no non-test TypeScript callers in server, CLI, app, or client source. Its `close()` sets status to `done` without evaluating acceptance criteria or dependent state, so this module is not wired as the production swarm coordinator. [Task store](https://github.com/getpaseo/paseo/blob/cf1a5a9e73a6dd3020fb62a6d10281a2193ff2f2/packages/server/src/tasks/task-store.ts#L17-L53), [close](https://github.com/getpaseo/paseo/blob/cf1a5a9e73a6dd3020fb62a6d10281a2193ff2f2/packages/server/src/tasks/task-store.ts#L281-L315).

For Infinite, transfer the durable subscription, explicit dispatch acknowledgement, and cursor-based reconnect. Work scope, retry authority, verified task acceptance, and the right to schedule a new attempt belong with the host that owns the assignment.

The operational follow-up traces PR digest coalescing, cross-host permission intersection, provider-specific tool policy, Git priority and protocol-version draining to their implementation. [Operational transfers](operations.md#which-existing-mechanisms-shorten-the-roadmap).

## Local verification

On Node 22 and Vitest 4.1.7, **239 tests passed in eight upstream suites**. Five suites covered keyed receipts, inbox delivery, timeline storage, the file task store, and dependency ordering (205 tests). Three more exercised finish subscriptions, JSON persistence and observation streams (34 tests). The cases include shutdown before notification acknowledgement, restarting from a persisted subscription, and loss of visibility on a remote host. The run used the pinned sources, upstream protocol generation and compiled protocol modules in an isolated harness. Remote observations used fixtures. A live two-daemon partition and the hosted Hub were outside these checks. [Message receipt cases](https://github.com/getpaseo/paseo/blob/cf1a5a9e73a6dd3020fb62a6d10281a2193ff2f2/packages/server/src/server/message-receipts/index.test.ts) · [Finish-subscription cases](https://github.com/getpaseo/paseo/blob/cf1a5a9e73a6dd3020fb62a6d10281a2193ff2f2/packages/server/src/server/agent/finish-subscriptions/finish-subscriptions.test.ts#L180-L245) · [Subscription storage cases](https://github.com/getpaseo/paseo/blob/cf1a5a9e73a6dd3020fb62a6d10281a2193ff2f2/packages/server/src/server/agent/finish-subscriptions/internal/json-store.test.ts).
